# 配置后的人工验收

本地自动化结果见 `../../docs/community-progress.md`。以下需要真实服务配置，尚未计为通过；不要把凭据、访问令牌或含会话的日志提交到仓库。

1. **U-1/U-2/U-4、I-2：GitHub。** 按部署说明创建OAuth App，配置回调和账号年龄限制；在浏览器完成授权登录、取消授权、账号绑定/重复绑定，在桌面端从本站入口授权并返回。退出桌面App后重新打开，确认登录保持。
2. **D-1：正式域名与TLS。** 设置域名解析与Caddy环境变量；在HTTPS地址检查首页、静态字体、上传图片和 `/healthz`。未配置下载地址时下载页说明缺失项，配置后确认macOS/Windows按钮指向实际下载文件。
3. **D-2：异地备份。** 配置独立的私有备份bucket，运行 `backup.sh`；确认对象存在并可由负责人下载，按 `restore.md` 在空目录恢复，检查帖子、账号和图片。当前已通过的自动化使用本地归档，不代表真实OSS权限已验证。
4. **P-9/W-2：OSS图片。** 配置图片bucket/CDN和CSP来源；上传头像、正文图片和作品封面，确认本站及嵌入模式均可显示。迁移旧图片前暂停服务，运行迁移脚本并检查正文、草稿、历史版本与头像引用，再切换存储驱动。
5. **I-6：实际模型对比分享。** 在已配置模型的App完成一次对比，分享摘要，核对卡片数字和来源摘要一致；发布后检查信息流。已自动验证字段提取、卡片、登录恢复与服务端拒绝非法数据，真实模型任务由负责人完成。

其余PRD手工流程可以按第13节逐项体验；Chrome自动化已覆盖无JS发帖、回复/点赞、草稿、搜索、作品封面、审核、390px和浅深主题，真实Electron自动化已覆盖独立会话、重启、外链、主题、离线重试和未读归零。
