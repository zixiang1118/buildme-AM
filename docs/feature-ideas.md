# BuildMe 新功能创意：让每次使用都产生一个可以验证的发现

日期：2026-10-07。状态：产品讨论稿，未进入实现。

## 产品判断

建议把下一阶段的体验串成：**完成自己的任务 → 注意到一个现象 → 改一个条件 → 对照结果 → 分享发现**。

现有产品已经覆盖了“看见、打开、比较、分享”。最有价值的增量，是帮助学生从“我看见它调用了工具”，走到“我知道下次该改哪里，以及怎样判断改得有没有用”。实验由学生自己的任务产生，不安排固定作业，不给学生判分，也不要求每次使用都停下来学习。

本稿依据 README、架构文档、X 光与社区 PRD、产品简报，以及能力、成就、X 光、讲解和对比的相关实现。当前代码已有九项扩展能力、30 项成就、两种引擎、两种对比方式、静态与按需模型讲解；这些不算新点子。社区代码与 App 入口存在，实际开放依赖网址配置和部署，不能据此宣称已经上线。

样图的本地 file URL 被浏览器安全策略阻止，本次只读取了 HTML 源码与设计说明，未进行视觉实测。建议沿用其陶土色、X 光蓝色、石墨色和积木语言，不另建一套视觉体系。

## 总览：按影响力 ÷ 开发量排序

### 成本口径

以下用 **B** 表示学生所选相近任务最近一次真实运行报告的总 token 用量，仅供预估。新跑一侧可先显示“约 B 量级”，两侧从相同基线重跑可显示“约 2B 量级”；真实调用次数、上下文、输出长度和子任务会让结果大幅变化。没有可参考的记录就显示“暂时无法可靠估计”，不能编一个精确预算。

静态查看、统计、编辑、导出和分享全部在本地或普通社区服务端完成，服务器不调用模型。每次额外运行都由学生点击触发，发送前展示所选模型、预计输入与输出预算；输出预算不等于整项 Agent 任务的费用上限。金额只有在单价、缓存计费口径和用量可用时才展示。

现有深入讲解已经能按需调用并缓存；新玩法优先复用它，不额外自动生成一层“AI 老师”。

## 01 本轮值得看的一幕

- **一句话：** 从刚结束的真实运行里，挑一个有意思的事件，让学生点一下就看懂。
- **命中的动力：** 好奇。
- **学生会怎么用：** 打开 App 完成自己的代码修改，回答下方出现一张小卡：“刚才工具报错后，它换了一种做法。”点开直接定位那两次调用及中间的模型响应。也可以遇到“这个 Skill 第一次被加载了”“这轮发生了上下文压缩”。
- **能学到什么：** 工具反馈会进入后续循环，Skill 加载有明确时点，长任务可能经历压缩；这些知识与自己的任务绑定。
- **依赖哪些现有模块：** Trace、X 光、静态讲解、成就的首次事件记录。
- **成本：** S；额外 0 tokens。第一版只选择少数可由事件直接确认的现象，不调用模型挑选。
- **风险或反感点：** 每回合强行弹出会打断工作。只在回答下方安静出现一张，可关闭；没有值得展示的事件就不出现。不得把“随后成功”自动写成“它发现错误原因并修好了”。

## 02 先看作品，再揭晓配置

- **一句话：** 先看两边做出了什么，再揭晓模型、Harness 和开销。
- **命中的动力：** 反差。
- **学生会怎么用：** 打开 App 的一组已完成对比，选择“先隐藏配置”，看匿名 A/B 的回答、文件差异与已有预览，选“更适合我”“各有优点”或直接揭晓。揭晓时才显示哪边是轻量版、哪边是全量版，以及各自的工具和用量。
- **能学到什么：** 能力多、模型贵、运行久，都不能直接替代对结果的判断；不同任务可能需要不同配置。
- **依赖哪些现有模块：** 对比结果、文件差异、X 光。
- **成本：** S；对已完成的对比额外 0 tokens；新对比仍按正常用量计费。
- **风险或反感点：** 回答内容本身可能泄露身份，不能宣传为严格盲测。没有标准答案，不评判学生的选择，不做模型总榜；工具调用少也不能自动判为更好。

## 03 只改一项，再跑一次

- **一句话：** 把现有双路对比扩展为学生可操作的单变量实验。
- **命中的动力：** 掌控、反差、好奇。
- **学生会怎么用：** 打开 App 给自己的网页增加搜索功能，跑完后点“只改一项”，选“是否使用计划”或“是否允许子 Agent”。界面保留同模型、同任务、同工作区起点，两边仅改变所选配置。学生可以先写一句“我猜会怎样”，也可以跳过，运行后看作品、过程、耗时和用量。
- **能学到什么：** Harness 的作用要放在具体任务中观察；会设计对照，比单纯背诵“计划有用”更有价值。
- **依赖哪些现有模块：** 能力开关、对比协调器、工作区隔离、X 光、文件差异。第一版限 Pi 对 Pi。
- **成本：** M；严格的新对照约 2B 量级，保留已有基线只补另一侧约 B 量级，但必须具备原始工作区和配置快照。缺失原始状态时，从当前起点重建两侧，不能冒充此前实验的复现。
- **风险或反感点：** 依赖会带来联动变化，例如关闭子 Agent 可能同时关闭工作流，界面要列出实际改变。模型随机性仍存在，一次结果只称“这次观察”；不默认自动重复多次。

## 04 Token 去哪儿了

- **一句话：** 把总 token 数变成可定位、可动手验证的用量账单。
- **命中的动力：** 好奇、掌控。
- **学生会怎么用：** 打开 App 跑完自己的任务，点用量数字，看到输入、输出、缓存读写与已记录子任务的分项。再沿模型调用查看上下文构成，定位占比大的工具输出；点“换一种读法试试”，在副本里比较“整份读入”和“先搜索再读相关部分”。
- **能学到什么：** 历史内容可能在后续请求中再次成为输入；工具输出也是上下文；缓存、任务完成度、延迟和 token 总量需要一起看。省字数不一定省下总任务成本。
- **依赖哪些现有模块：** Trace usage、上下文构成、工具结果、对比。新增的是跨调用的支出视图与实验入口，不重复已有上下文条形图。
- **成本：** M；查看账单额外 0 tokens；验证一条改法约 B 量级，完整对照约 2B 量级。
- **风险或反感点：** 当前数据不足以精确分摊每一条消息的实际费用。请求级 usage 可实测，内容级归因只能按估算标注；截断或缺失数据要显式标出。重复读文件只能提示为现象，不能自动断言浪费；不能把少读必要信息当优化。

## 05 Skill 试衣间

- **一句话：** 给同一个任务“穿上”两版 Skill，观察实际变化。
- **命中的动力：** 掌控、反差、被看见。
- **学生会怎么用：** 打开 App，选自己在用的一份 Skill，界面分出“什么时候用、操作步骤、参考资源、如何检查结果”四个阅读区域。学生只修改触发描述或一个步骤，再拿自己的任务做对照：目录里是否出现它、是否加载正文、加载后调用了什么、最后作品怎样。两个版本都能保存为本地草稿。
- **能学到什么：** Skill 的适用条件、渐进加载、步骤与资源组织，以及如何用真实任务验证改动。让学生自己遇见“Skill 没被用上”和“更长却没有更好”这样的现象。
- **依赖哪些现有模块：** Skill 目录与加载事件、提示词来源、能力开关、对比、X 光。
- **成本：** M；手工编辑与静态拆解 0 tokens；每次单侧试用约 B 量级，双版本约 2B 量级。首版不自动生成 Skill、不默认批量运行。
- **风险或反感点：** 不提供没有依据的“优质 Skill 评分”。必须区分“可见”“已加载”“后续行为符合某个步骤”，不能声称知道模型选择它的内部原因。脚本执行继续遵守原有权限。

## 06 借走同学的 Agent 配方

- **一句话：** 同学分享的是一套能看懂、能改动、能试用的配置。
- **命中的动力：** 被看见、掌控、反差。
- **学生会怎么用：** 打开 App 社区，看到同学展示的课表网页，点“看看怎么搭的”，查看他公开的能力组合、提示词片段和 Skill 清单。点“在我的项目上试试”，先看与自己配置的差异，再用自己的模型连接建立临时实验，不覆盖日常配置。
- **能学到什么：** Agent 的效果来自模型、规则、工具和上下文的组合；优秀配置有适用条件，移到另一个任务未必同样有效。
- **依赖哪些现有模块：** 能力开关、社区帖子/作品、模型连接、对比、配置快照。
- **成本：** M，首版只做 Pi 能力与用户明确选中的文本配置；分享、预览、导入 0 tokens，试用约 B 量级。跨引擎自动转换和依赖自动安装不在首版内。
- **风险或反感点：** 不分享 Key、聊天、绝对路径和整个工作区；资源缺失时清楚列出。只发布配方不能保证复现相同作品，卡片用“试用同款配置”，不是“完全复现”。不自动运行配方中的脚本。

## 07 这一刻，它能看见什么

- **一句话：** 沿着时间线移动，看到每次模型请求实际包含哪些信息。
- **命中的动力：** 好奇。
- **学生会怎么用：** 打开 App 的一次历史任务，把时间游标停在出错前的一次请求。界面按来源列出当时在上下文里的消息、工具结果、规则与摘要，并显示“已截断”“完整内容未记录”等状态。学生能直观看到：文件在工作区里，不等于其内容已经进入了这次请求。
- **能学到什么：** 模型的可见上下文、文件系统和跨回合历史不是同一件事；“你刚才不是看过吗”可能涉及读取、裁剪或摘要。
- **依赖哪些现有模块：** X 光、请求快照、提示词来源、上下文压缩事件。
- **成本：** M；额外 0 tokens；先覆盖记录完整的 Pi 回合，其余按 fidelity 显示支持范围。
- **风险或反感点：** 只能说明记录中的请求包含了什么，不能说明模型实际注意到了什么，更不能画成模型内部思维热力图。raw 被清理或截断后，不得把“没有记录”标成“当时没看见”。

## 08 这条规则从哪里来

- **一句话：** 让学生顺着一条提示词，找到它的来源、加载时机和适用范围。
- **命中的动力：** 好奇、掌控。
- **学生会怎么用：** 打开 App，发现 Agent 总是先写计划。在 X 光中选中“先制定计划”这段文本，查看它来自哪个已记录的提示词段、能力或工作区规则；切换能力后，在下一次请求中看这段是否仍存在。相似或表面矛盾的文本可以并排阅读。
- **能学到什么：** 系统提示词、工作区说明、Skill 与用户请求的来源不同；修改一份文件是否影响运行，取决于该 Harness 的实际加载方式。
- **依赖哪些现有模块：** 提示词分段、sourcePath、上一回合差异、能力开关、静态知识说明。
- **成本：** M；来源关联与差异查看 0 tokens。验证修改后的行为需要学生另行运行任务。
- **风险或反感点：** 不能只按文本位置给出普适的规则优先级，也不能凭词句冲突宣称某条规则一定被覆盖。DSH 没有提供的原始段来源不补猜测；不自动改写工作区规则文件。

## 09 “做完了”的证据

- **一句话：** 在 Agent 的完成声明旁边，放上它实际留下的检查证据。
- **命中的动力：** 掌控。
- **学生会怎么用：** 打开 App 让 Agent 修网页，收到“已经修好”后，卡片列出改了哪些文件、记录中运行了哪些检查、哪些工具失败。学生可点开原始结果，并勾选自己关心的“页面能打开”“搜索功能能用”等条件，记录亲自观察到的结果。
- **能学到什么：** Vibe Coding 也需要验证；模型说完成、命令退出成功、作品满足要求是不同层次。知道下一次应让 Agent 提供什么证据。
- **依赖哪些现有模块：** 工具调用/结果、文件差异、对比结果；首版只聚合已有证据。
- **成本：** M；展示与手工标记 0 tokens。执行已有检查命令本身不必调用模型，但耗本机资源；如果让 Agent 决定和执行检查，则按该次运行实计。
- **风险或反感点：** 不给学生打分，不设置平台统一作业。工具没有报错不等于测试通过；不知道某条命令的含义就展示原始记录，不推导“质量达标”。

## 10 我的发现卡

- **一句话：** 把一次个人观察变成带证据的社区内容。
- **命中的动力：** 被看见、好奇。
- **学生会怎么用：** 打开 App，选中自己刚完成的对比，点“记下这个发现”。卡片给出三个可留空的小栏：“我改了什么、这次发生了什么、我还想试什么”，并让学生手动选择愿意公开的统计或事件。确认预览后保存图片或进入发帖草稿。
- **能学到什么：** 区分观察与解释；为观点附上任务条件与运行证据；从同伴的不同结果中发现新问题。
- **依赖哪些现有模块：** 对比分享、X 光、社区。增量是学生自己的假设、观察和选定事件，不重复已有统计卡。
- **成本：** M；额外 0 tokens，使用本地模板，不自动代写结论。
- **风险或反感点：** 不变成必填实验报告。默认只选择非内容统计，路径、提示词和工具结果须逐项预览；单次卡片不生成“某模型一定更强”的标题。

## 11 作品的成长过程

- **一句话：** 让作品墙能展示一次作品怎样从初稿变到最终版本。
- **命中的动力：** 被看见、好奇。
- **学生会怎么用：** 打开 App 做完自己的网页，手动挑选两个或三个节点，为每个节点选截图并写一句“这里我改了什么”。作品页能展开查看“加了什么要求、换了什么配置、结果发生什么变化”，同学从一个具体改动继续讨论。
- **能学到什么：** 需求表达、迭代、验证与上下文组织；别人做出好作品的过程也有反复。
- **依赖哪些现有模块：** 作品墙、图片上传、帖子、会话与对比记录。
- **成本：** M；额外 0 tokens；首版手动选择节点与素材，不持续截屏，不自动生成视频。
- **风险或反感点：** 发布过程不能比发布作品复杂很多。只公开作者选择的节点，不上传完整聊天，不把更少迭代当作更强的标准。

## 12 从经历长出来的知识地图

- **一句话：** 概念节点连接到学生自己经历过的运行片段。
- **命中的动力：** 好奇、掌控。
- **学生会怎么用：** 打开 App 的探索足迹，点“上下文”，看到自己第一次压缩的回合；旁边关联“工具输出”“Skill 按需加载”“子 Agent 的独立上下文”。点击任一已经历节点，就回到自己的实例与静态说明；未经历的节点只有解释和可选探索入口。
- **能学到什么：** 将零散经历组织成 Agent 知识结构，知道下一个自己感兴趣的问题在哪里。
- **依赖哪些现有模块：** 成就、Trace、静态知识、X 光。
- **成本：** M；额外 0 tokens。概念关系人工维护，实例绑定来自真实事件。
- **风险或反感点：** 看到事件不能自动推断“已掌握”。不用完成率、连续打卡或班级排名施压；历史已清理时保留概念，不伪造实例。

## 13 一句话怎样变成 Token

- **一句话：** 让学生在本地拆开自己刚输入的一句话，观察分词与请求包装。
- **命中的动力：** 好奇。
- **学生会怎么用：** 打开 App，选中自己的一句需求，点“拆开看看”，看到支持的分词器如何把中文、英文、数字和代码分成 token。接着展开“发送时还带了什么”，连接到系统提示词、工具定义和历史消息。
- **能学到什么：** 字数与 token 数不等同，单条输入与整个模型请求也不等同；同样的文字在不同分词器下可能不同。
- **依赖哪些现有模块：** 输入框、模型信息、请求快照、静态知识。另需核实并接入有明确版本的本地分词器。
- **成本：** M；本地查看额外 0 模型 tokens；分词器资源会增加包体与维护成本。
- **风险或反感点：** 当前的字符估算不能伪装成精确 token 切片。只对明确支持的分词器展示实分词；其余标注估算。即使正文分词精确，也不等于供应商报告的整个请求计费用量。

## 14 下一步，我来选

- **一句话：** 在工具真正执行前，学生可以观察并改变一次行动。
- **命中的动力：** 掌控、反差。
- **学生会怎么用：** 打开 App，在自己的实验副本开启“逐步走”。模型提出读取整份大文件时，界面停在工具执行前，学生可按原计划继续，或选择先搜索并读取相关部分。之后观察新结果怎样进入下一次模型调用。
- **能学到什么：** Agent 循环中，模型负责提出行动，Harness 负责执行与反馈；工具设计和人的干预可以改变后续路径。
- **依赖哪些现有模块：** 工具审批、工具执行入口、X 光、独立实验副本；需要新增执行暂停与介入记录。
- **成本：** L；暂停和查看 0 tokens。仅修改工具参数未必立即产生额外模型调用；要求重新规划会增加调用，后续总用量按实际记录。
- **风险或反感点：** 容易做成面向工程师的调试器。首版只支持少数只读工具，明确区分原模型建议和人的改动；不能只暂停 UI 而让命令继续执行。不要将暂停时间计入模型推理耗时。

## 15 从这里走另一条路

- **一句话：** 从一次运行中的关键节点分出新路线，对照后续结果。
- **命中的动力：** 掌控、反差、好奇。
- **学生会怎么用：** 打开 App 看自己的运行回放，在“开始大范围修改”之前点“从这里另试一次”，补一句“只修这个问题”，在新副本继续。两条路线并排显示后续读取、改动和开销。
- **能学到什么：** 任务约束、当时上下文和工具反馈会共同影响路径；何时介入比盲目追加长提示词更值得观察。
- **依赖哪些现有模块：** Trace、会话、对比、工作区隔离；另外需要模型请求边界的可恢复会话与文件检查点。
- **成本：** L；回放 0 tokens，新分支消耗其后续真实用量，没有统一固定数字。
- **风险或反感点：** 现有 Trace 是观察记录，不能直接当作可执行检查点。文件、进程、外部接口状态未必可还原；首版只对记录完整且支持恢复的 Pi 本地任务开放。更便宜的起步方案是功能 03 的整项任务重跑，不能把它宣传成任意时刻回溯。

## 16 压缩之后，它还记得吗

- **一句话：** 学生挑选自己在意的信息，观察压缩前后保留了什么。
- **命中的动力：** 好奇、反差。
- **学生会怎么用：** 打开 App，在自己的长任务里标记“只改移动端布局”这条约束。当已有运行发生压缩后，展开原始片段与摘要，看约束是否被明确保留；愿意进一步探索时，主动开启带不同摘要策略的后续对照。
- **能学到什么：** 压缩在容量、成本和信息保留之间取舍；把关键约束写清楚、保存状态、按需重新读取有各自作用。
- **依赖哪些现有模块：** 压缩事件、摘要、原始请求、X 光、对比；实验还需可控的摘要策略与可恢复边界。
- **成本：** L；读取已有记录 0 tokens；主动重新压缩与运行分支分别计费，按实际输入和所选输出预算预估。
- **风险或反感点：** 字面没出现不代表语义丢失，字面出现也不保证之后遵守。让学生看文本与行为证据，不伪造“记忆准确率”；不鼓励为了触发压缩故意消耗大量 token。

## 17 在副本里，给它制造一点意外

- **一句话：** 用学生自己的任务，试一次受控的工具失败或信息缺失。
- **命中的动力：** 好奇、掌控。
- **学生会怎么用：** 打开 App 的实验副本，选中一次只读工具调用，选择“这一次返回文件不存在”或“只返回部分内容”，再让 Agent 继续。看它会核实、换工具、请求帮助，还是在缺信息时继续声称完成。
- **能学到什么：** 工具结果与错误处理也是 Harness 的一部分；重试、重新规划、停止和求助有不同适用条件。
- **依赖哪些现有模块：** 工具调用层、X 光、隔离对比、完成证据；需新增明确标记的实验结果替换机制。
- **成本：** L；配置 0 tokens，试运行约 B 量级但可能因失败处理变长；用户可随时终止。
- **风险或反感点：** 只在明确标识的实验副本里模拟，默认限定只读工具，不损坏真实文件。所有模拟事件与导出卡必须标明“人为注入”，不能混成模型自然发生的失败；不预设一定存在理想恢复方式。

## 18 把外面的 Agent 带进 X 光

- **一句话：** 让学生用熟悉的日常工具干活，再把支持的记录带回 BuildMe 学习。
- **命中的动力：** 好奇、被看见。
- **学生会怎么用：** 打开 App，主动选择一份某个外部 Harness 支持导出的本地记录。BuildMe 先列出能读取的字段、缺失字段和支持的版本，再转换成只读时间线；学生将其中一次“读文件→修改→检查”的过程与自己的 BuildMe 运行并排看。
- **能学到什么：** 不同工具共享哪些 Agent 概念，哪些行为是特定 Harness 的实现选择；把在 BuildMe 学到的观察方法迁移到日常 Vibe Coding。
- **依赖哪些现有模块：** Trace 格式、fidelity、X 光、静态讲解；新增版本化导入器。
- **成本：** L；纯本地导入与查看 0 tokens。首版只选择一个已核实有足够记录的来源，不承诺同时支持 Claude Code、Codex 和 Cursor。
- **风险或反感点：** 外部产品的导出格式、字段和权限需要单独核实，本稿未验证任何一家的完整日志可用性。缺少提示词、费用、内部推理或工具细节就显示不可用；不扫描账号目录、不抓取闭源内部数据，不宣称能完整透视外部 Agent。

## 最推荐的前五个与建议顺序

“投入产出排序”和“形成完整产品体验的推荐组合”不完全相同。建议第一组做 01、03、04、05、06，分别解决发现入口、验证方法、成本理解、Skill 实践与同伴传播。

| 建议顺序 | 功能 | 为什么优先 | 放在哪个里程碑之后 |
|---|---|---|---|
| 1 | 01 本轮值得看的一幕 | 开发相对小，直接改善首次体验，让更多人从完成任务走进 X 光 | M1/M3 后即可；当前可作为 M5 后的小增量 |
| 2 | 03 只改一项，再跑一次 | 最直接教会学生怎样使用和调整 Harness，也为其他玩法提供共同的实验底座 | M4 的隔离对比、M5 模型对比之后 |
| 3 | 04 Token 去哪儿了 | 对学生有立刻可感知的实用价值；结合 03，能验证改法而不是只看数字 | M5 的用量口径与保真边界明确后；与 03 相邻 |
| 4 | 05 Skill 试衣间 | 把抽象 Skill 知识变成可操作、可观察的个人经验 | M2/M5 后，并复用 03 的版本对比能力 |
| 5 | 06 借走同学的 Agent 配方 | 让一个人的发现变成另一个人的实验理由，给社区提供持续内容 | 本地预览可在 M2 后；社区流转接在 C7 App 集成可用之后 |

M0–M5 的进度文档记载已落地，排期应从其当前基础继续。C7 是否可供真实同学使用，还要以实际部署和配置为准，不能把代码完成当作社区已开放。

最初只上线两项时，选 **01 + 03**。想先展示一个更有冲击力的方向，可以为 **15 从这里走另一条路** 做单独技术验证；先核实恢复能力，再决定产品承诺。

## 第一次十分钟可以怎样发生

学生打开 App，直接做自己本来想做的事情，例如修改个人网页。第一次完成后，回答下方出现一幕可解释的真实事件；他点开看见工具如何反馈。接着选择只改变一项能力，主动确认额外运行，比较两次结果，查看用量账单。最后可以保存一句“我以为会更快，结果……”的发现，也可以直接结束使用。

这只是理想路径，不设置必须按顺序完成的教学步骤。模型等待时长与任务复杂度不可控，“十分钟”是设计目标，不是现有性能承诺。用户没有 Key 时，可以看明确标为“示例回放”的随包记录；示例应来自经许可的真实运行，不能伪装成正在进行的调用。

## 需要守住的产品取舍

1. **用学生的任务提供探索入口。** 固定题库、考试、每日打卡、学生能力排行榜不纳入本轮。
2. **所有数字旁边保留作品与完成证据。** 不鼓励为少 token 而少做必要工作，也不以调用多寡判定聪明程度。
3. **X 光展示可观察的运行事实。** 可以解释请求、调用、工具结果和已提供的模型输出；不能把事后生成的讲解当作模型真实内部思维。
4. **默认轻，按需深。** 第一层是一幕现象和一个入口，完整图表、日志、分词和调试留给主动展开的人。
5. **分享必须有可预览的边界。** 分享配置与选定证据，不顺带上传原始会话、整个工作区或凭据。导入与试运行沿用现有权限。

## 外部依据与本稿推断的边界

- Anthropic 的 [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) 讨论了上下文选择、按需检索、压缩与结构化笔记的取舍。本稿据此提出可见性、用量和压缩玩法；这些交互能否提高学习兴趣仍需实际观察。
- Anthropic 的 [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) 说明了 Skill 的组织与渐进披露。Skill 试衣间是本稿的产品设计建议，不是来源已有的教学结论，也不表示所有 Harness 的加载实现相同。
- Anthropic 的 [Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 讨论任务、运行轨迹与结果评价。本稿借用“看证据、看结果”的工程方法来设计个人实验，不将其变成学生考试。

## 待决问题

以下不阻碍讨论创意，但应在对应 PRD 中决定，不能在实现时偷偷扩张范围。

1. **首批优先级：** 是优先减少新手进入 X 光的门槛，还是优先服务已经熟悉 Agent 的同学？本稿的 01 + 03 是推荐组合，尚未排期。
2. **Skill 编辑范围：** 第一版支持纯 Markdown 与显式选取的参考文件，还是同时允许脚本、依赖和资源包？后者会扩大开发量与执行边界。
3. **用量与预算：** 实际常用 provider 返回哪些缓存与辅助调用数据？是否已有维护可靠的价格表？在核实前只承诺分项 token 与估算，不承诺精确人民币账单。
4. **配方共享：** 首批允许公开哪些文本、资源与模型元数据？是否提供作者确认可分享的小型任务素材？没有共同素材时仅称“试用同款配置”。
5. **中途分支与暂停：** Pi/DSH 分别有哪些可用的持久检查点和控制接口？历史 raw 的清理、截断以及工作区副本过期怎样限制入口？先调研，再写可恢复范围。
6. **外部工具：** 先支持哪一个具体产品、版本和记录格式？应以真实可获取的样本决定，不先许诺三个产品全支持。
7. **老师视角：** 是否确实需要另一个班级页面？若需要，先讨论仅由学生主动分享的聚合发现与作品，不默认采集个人聊天、操作轨迹或学习时长。

本次只新增此创意文档，未实现上述功能，未调用学生模型 Key，未发布社区内容。
