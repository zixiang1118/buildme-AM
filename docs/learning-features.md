# 发现卡与 Token 账单

交付日期：2026-10-07。

## 使用入口

- 回合结束后，回答下方出现 **Token 去哪儿了？**。也可从 X 光的 **Token 账单** 标签进入。
- 如果该回合记录到工具报错后的不同调用、上下文压缩或 Skill 加载，回答下方展示一张 **本轮值得看的一幕**。点击标题定位并高亮对应事件；可逐张收起，也可在设置的 X 光记录区关闭全部发现卡。
- 账单内点击 **先搜索，再试一次…**，预览共同任务、模型连接和预计额外用量，建立副本后点击 **同时运行**。单纯查看、预览和建立副本不会调用模型。
- 对比结果的每一侧也提供 **Token 账单** 入口。

## 展示口径

账单分别显示普通输入、输出、缓存读取和缓存写入。父子回合按身份去重；关联子回合缺失或跨 worker 采集不完整时不展示任务合计。未报告的项显示“未提供”，不以 0 代替。

请求按输入量排列，并可定位原始事件。工具输出显示对应工具与已记录的文件路径、出现在哪些请求、单次和累计估算占用。完全相同的历史消息通过内容指纹识别，展示重复进入哪些模型请求。这里的累计占用不是重复计费，也不等于浪费。

新运行会记录不含正文的逐条上下文占用元数据，独立于原始请求记录开关。旧历史没有这些数据时，只展示已保存工具输出的长度估算，不推断它进入了多少次请求。图片和序列化结构的字符估算不等同于供应商实际计费。本版不估算人民币费用。

发现卡由本地确定性规则生成，每个回合最多一张。错误后的调用变化不被描述为“已修好”；Skill 的第一次明确限定为本回合，不能当作用户生涯中的第一次。

## 读取策略实验

两侧均使用 Pi、同一模型连接、相同能力和当前工作区的新副本；两侧临时加入工作区搜索能力，不改变用户的日常能力配置。左侧要求直接读取相关文件，右侧要求先搜索再分段读取。双方都需要完成原任务并说明实际检查证据。

实验不会恢复旧回合的文件或聊天状态，开始前应补充任务所需的上下文。策略通过指令给出，是否遵守以 X 光中的实际工具调用为准。沿用既有隔离、审批、停止和采用改动流程。

## 实现位置

- `src/core/trace.ts`：发现卡规则与历史摘要。
- `src/core/trace-context.ts`：不含消息正文的逐条上下文占用。
- `src/core/trace-ledger.ts`：请求、工具输出、重复内容和父子回合账单。
- `src/core/trace-collector.ts`、`src/full/dsh-trace.ts`：Pi / DSH 采集；补齐 Pi 缓存写入用量。
- `desktop/main.mjs`、`desktop/preload.cjs`（Electron 实际入口）、`desktop/preload.mjs`：本地账单接口与结束事件。
- `desktop/renderer/xray.js`、`xray-ledger.js`、`index.html`、`style.css`：发现卡、账单与事件定位。
- `src/core/compare-coordinator.ts`、`desktop/compare.mjs`、`desktop/renderer/compare.js`、`renderer.js`：同模型读取策略对照。
