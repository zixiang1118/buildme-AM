# 科研平台搭建器

科研版提供一个可以改造的平台搭建器。它不预设研究方向，也不要求所有课题都按同一条流程开展。你可以搭建多个平台，为不同课题配置各自的页面、记录字段、能力、助手和工作流程。

BuildMe 的原版、学习版和科研版都保留，可以在版本菜单中切换。**“我的科研平台”入口位于右上角、设置按钮前面，仅在科研版显示。** 平台内附带“搭建与使用说明”，随时可以查阅。

## 第一次使用，按这四步开始

1. **搭建**：切换科研版，打开右上角的“我的科研平台”，进入“平台搭建器”，挑选需要的科研积木。每选一个模块，右侧就增加一块立方体积木。
2. **调整**：拖动积木调整顺序，也可以使用上移、下移；检查页面、字段、能力、助手和流程，在“使用预览”确认表单。
3. **保存**：点击“保存并进入对话”，检查摘要并确认，保存后自动选中这个平台并返回对话。
4. **使用**：直接在对话中发送记录、导入、分析或运行流程的请求。助手会调用平台能力实际执行，再根据真实结果回答。

例如，搭建“数据分析”积木后，在聊天中添加 CSV、TSV 或 Excel 文件，发送“把附件导入当前平台，按分组计算均值和标准差，并说明缺失值”。助手会读取完整表格原件，保存导入与分析结果。表头应与搭建时配置的字段名称或编号对应；有多个来源页面时，请说明要导入哪一个页面。

科研积木已整合进“我的科研平台”的平台搭建器，替换原来的“挑选你的科研积木”功能。搭建和使用在同一套平台中衔接：选择积木搭好平台，保存后就能在对话里使用。保存平台不会自动运行任务；你发送具体请求后，助手才会执行。

## 从哪里开始

进入科研版的“我的科研平台”→“平台搭建器”，可以直接搭建模块组合。当前提供数据集管理、代码运行、实验比较、图表与报告、样本管理、实验方案、实验记录、数据分析、检索记录、文献筛选、综合写作 11 个模块。

模块可以自由增减，积木和下方清单同步更新。拖动积木可调整模块顺序，也保留上移、下移操作；积木添加、移动和移除时会平滑过渡。名称、用途、模块选择和保存均在平台搭建器内完成。保存后生成对应页面与能力，并自动返回对话；继续搭建会恢复已选模块和顺序。数据分析、实验比较各自提供数据记录与分析页面，可以独立使用。移除模块不删除已有研究记录、归档文件和运行历史。

代码运行模块保存脚本、参数和运行记录，“准备代码运行”通过已配置的 Agent 和工具执行。模块选择本身不会运行代码或触发模型请求。

### 创建自己的模块

模块列表最后的 **“＋ 自定义模块”** 提供两种方式：

- **自己设计**：填写模块名称与用途，在“页面与字段”中添加记录、笔记或分析页面，设置文本、数值、日期、选项和多行文本字段；在“模块能力”中选择所需能力。
- **让 AI 生成**：描述模块需要保存什么资料、如何分析、需要哪些页面与字段，点击“让 AI 生成”。程序使用已经配置的模型连接生成模块草案，随后打开同一个编辑器，供你修改并查看“使用预览”。

例如，可以输入：

> 我需要一个设备校准模块，登记设备编号、校准日期、标准值、测量值和操作人，并按设备查看误差。

AI 生成后不会自动保存。检查字段类型、单位与分析数据来源，点击 **“保存模块并加入组合”**，才会把模块保存到当前工作区的模块库并加入正在搭建的组合。这个操作只保存模块；仍需点击平台的“保存并进入对话”并确认，才会创建科研平台并进入对话使用。

自己的模块可以与内置模块组合，重启后仍在当前工作区的模块库中，可在其他平台重复使用。模块定义提供页面、字段和已支持的能力；专业工具仍需按需接入。

## 调整平台

搭建器将配置分为六个页面：

| 页面 | 可以调整的内容 |
| --- | --- |
| 积木模块 | 自由选择模块，预览立方体积木组合；拖动或使用上移、下移调整顺序，自动配置对应页面和基础能力 |
| 页面与字段 | 增删、改名、排序页面；选择记录、分析或笔记类型；定义文本、数值、日期、选项、多行文本字段，设置单位与必填要求 |
| 能力与助手 | 选择记录、文件、统计、绘图和笔记能力；设置助手职责、工作要求及模型连接 |
| 工作流程 | 按顺序连接导入、分析、报告步骤，选择数据来源与分析字段 |
| 使用预览 | 查看配置生成的表单和分析页面；预览阶段不保存研究记录 |
| 高级配置 | 直接修改平台 JSON；保存时会校验配置和关联关系 |

分析页面需要选择一个记录页面作为数据来源，再指定数值、分组和样本编号字段。字段名称可以改，字段编号用于关联数据；使用高级配置时，改名应保留原有编号。

点击“保存并进入对话”创建平台。已经创建的平台使用“继续搭建”修改，完成后点击“保存变更并进入对话”。保存前会显示变更摘要，点击“保存并进入对话”确认后，自动启用这个平台并返回聊天。移除页面或字段不会删除历史记录中的旧值；改变字段类型不会自动把旧值转换成新类型，后续分析需要检查这些数据。

## 通过 Agent 设计并审查草案

需要模型的搭建与改造任务使用 BuildMe 中已配置的模型连接。可以在平台的助手设置中指定连接，留空则使用当前模型。

发送搭建任务后，Agent 读取当前平台目录与配置，并通过 `platform_propose` 提交草案。草案不会直接替换平台，也不会改写原始记录。

Agent 完成后重新打开“我的科研平台”，在“Agent 提交的平台草案”中点击“查看并继续搭建”。检查页面、字段、能力和流程，必要时继续调整，再通过保存按钮应用。改造已有平台时，草案对应的配置版本必须仍然有效；版本已变化时需要重新核对或生成草案。

## 保存后，直接在对话里使用平台

保存并确认后，会自动回到对话并选中刚搭建的平台。以后可以通过右上角“我的科研平台”切换已有平台，继续在对话里使用。记录管理页面仍可打开，方便查看、编辑资料和核对运行过程，无需先去那里点击运行。

**聊天前先看右上角显示的当前平台名。** 点击“我的科研平台”可以直接切换平台，也可以选择“不启用平台”。停用后使用当前模型，不带入平台配置；这个选择会按工作区保存，重启后仍然有效。需要继续使用时，重新选择已有平台即可。

点击“搭建与管理平台”，在“已经搭建的平台”卡片上选择“删除平台”，确认后将平台移出列表。如果删除的是正在使用的平台，会同时停用，其他平台不会自动启用。平台配置、记录、附件和运行历史会保留在工作区的本机归档中。

每轮发送消息时，BuildMe 会带入**当前选中平台的配置**：页面、字段、能力、助手职责、工作要求和流程。平台指定了模型连接时，本平台的对话会使用该连接；留空时使用当前模型。

平台配置会自动带入；研究记录与运行结果由 AI 通过工具**按需读取**，不表示每轮都会无条件上传全部记录或附件。若要解读某次结果，请说明目标页面、分析或问题，也可以从结果区点击“让助手解读这个结果”。

例如，可以直接发送：

> 请把样品 A 的浓度 2.4 和样品 B 的浓度 3.1 保存到当前平台的样品记录中，单位是 mg/L，并告诉我保存结果。

> 请使用当前平台的数据分析模块，按已配置的字段运行分析，再解释缺失值、分组均值和样本数。数据不足时请说明，不要补造数据。

> 请运行当前平台已保存的工作流程，逐步报告实际完成的步骤；需要导入文件时先说明所需文件。

已经有分析结果时，可以发送：

> 请读取当前科研平台的最新分析，按照助手设置检查缺失值与样本独立性，解释结果，并提出下一步需要验证的问题。区分原始记录、计算结果和研究建议。

要改造平台，可以发送：

> 请查看当前平台，在样品记录中增加设备编号，并检查已有分析与流程是否仍然适用。保留已有数据，先提交可预览的草案供我确认。

需要注意两种约束的区别：

| 设置 | 当前怎样生效 |
| --- | --- |
| 助手职责、工作要求 | 作为 AI 的工作指引，帮助它按当前课题回答；仍需核对回答和证据 |
| 字段类型、必填、配置关联、版本 | 由程序校验；不符合要求时会阻止保存或执行，并提示原因 |
| 已保存的工作流程 | 保存步骤与参数；发送运行请求后执行，也可在管理页面手动运行，不会因为保存平台或打开聊天就自动启动 |
| AI 提议的平台改造 | 保存为草案；由你预览、调整并确认后应用 |

聊天既可以讨论研究设计和解读结果，也可以直接请求新增记录、导入文件、运行统计和完整流程。助手会调用当前平台已有的能力，记录实际输入、操作与结果；缺少数据、文件、配置或工具时会明确说明，不会把建议当成执行结果。平台内“准备任务”类按钮仍会先填入聊天内容，需要你发送后 AI 才开始处理。修改页面、字段和流程等平台结构时，仍先提交草案，由你预览并确认保存。

切换课题时，先选中对应平台，建议新建对话，减少此前课题的聊天内容对新任务的影响。切到原版或学习版后，平台专属配置不再作为新一轮的科研上下文带入；平台数据仍保留在原工作区。

## 使用自己的平台

### 记录和笔记

可以在对话中说明要保存的记录和字段值，发送后由助手保存并反馈结果；需要修改时说明目标记录及变更内容。记录管理页面按照你定义的字段显示表单和表格，也可以在那里新增或编辑。笔记页面保存标题、内容或其他自定义字段。

记录区分用户录入、文件导入和教学示例。来源标签描述资料的来历，不等于已经证明实验有效或独立。示例数据不会被当作真实研究结果。

### 导入文件

在对话中说明要导入的 CSV、TSV 或 XLSX 文件及目标记录页面，提供可访问的本机文件路径，助手会调用平台导入能力。也可以在记录页面点击“导入 CSV / Excel”选择文件。表头应与该页面的字段名称或编号对应。文件会先归档，再读取归档副本并映射字段；导入后检查单位、缺失值和来源说明。

空白数值保留为空值，不会补成零。无法解析的数值、缺少必填字段或不匹配的表头会明确提示。已经归档的文件可在“过程与版本”查看，也会包含在课题导出中。

### 分析和绘图

启用统计能力并配置好数值、分组和样本编号字段后，可以在对话中请求运行对应分析；也保留分析页面的“运行分析”按钮。真实计算包括：

- 同一分组、同一样本编号的重复读数先求平均。
- 各组显示样本数、有效读数、均值、标准差、中位数和范围。
- 缺失值排除并说明；只有一个样本时不计算样本标准差。
- 未指定样本编号时，每条记录按一个统计单位处理，并提醒核对实验独立性。

启用绘图能力后，图中柱形表示分组均值，点表示原始数值读数。教学示例点单独标色。数值、输入记录、处理参数与配置版本都保存在运行记录中；输入记录后来发生变化时，界面会提示重新运行。

这一步是描述统计，不会自动生成显著性、因果或疗效结论。“让助手解读这个结果”会准备聊天任务，方便进一步讨论方法和结论范围。

### 执行流程

在对话中发送“请运行当前平台的工作流程”，助手会按保存的步骤实际执行。也可在平台总览中点击“运行流程”：

1. **导入**：使用你提供的文件；从管理页面运行时可通过文件选择器选择，随后归档文件并导入记录。
2. **分析**：按照流程参数或分析页面的默认配置运行描述统计。
3. **报告**：根据已保存的分析结果生成数值摘要，附上来源和运行关联。

缺少数值字段、数据、统计能力或有效来源配置时会报错。取消或失败不会假称整个流程成功；已经完成的步骤及运行记录仍然保留，可以在“过程与版本”检查。

## 能力的实际范围

本版可直接运行记录保存、文件导入、描述统计、绘图、笔记、流程报告、版本恢复和导出。

文献、化学和仿真属于可选的助手指导能力。对应按钮会准备研究任务，交给当前 Agent；专业计算工具、检索工具和所需资料需要自行接入。仅勾选能力不会自动安装仿真软件、化学计算引擎或连接实验设备。助手应区分设计建议、待配置的能力与已经实际执行的结果。

## 导出、复用与恢复

- **导出课题资料**：保存平台配置、记录、运行输入与结果、版本历史、原始文件及文件指纹，方便备份与核查。
- **另存为模板**：只保存平台结构和设置，方便同组同学导入并改造；不包含实际记录和原始文件。
- **导入平台模板**：从首页导入 BuildMe 平台模板，创建一个独立平台。
- **恢复版本**：在“过程与版本”选择历史结构，恢复后创建新版本；当前研究记录、文件和运行历史保留。

平台数据保存在所选工作区的 `.buildme/platforms/<平台 UUID>/` 中，配置与记录位于 `snapshot.json`，导入文件位于 `assets/`。平台 UUID 用于区分同名课题。更换工作区后，显示的是新工作区中的平台。

旧固定药物研究工作台已经从当前产品入口与执行流程中回退。原有 `.buildme/research/` 课题档案和此前导出的资料没有删除；它们不会自动变成新的通用平台。需要复用时，可以保留备份，再按新的字段导入所需数据。

## 开发验收

在项目目录中执行：

```powershell
pnpm build
pnpm test
pnpm lint
node scripts/verify-platforms-electron.mjs
```

前端专项回归可单独运行：

```powershell
node node_modules/vitest/vitest.mjs run test/platform-renderer.test.mjs
```

专项检查涵盖自定义字段创建、结构版本校验、旧值保留、空值处理、真实流程调用、统计结果与原始点显示、分析页面类型切换、Agent 草案审查、三种版本切换及不受信任文本的安全显示。平台存储、导入、服务和 Agent 工具的测试另行验证实际计算、档案持久化、路径边界和导出内容。测试不调用收费模型，不连接真实实验设备。

运行 `node scripts/verify-platform-modules-electron.mjs` 可验证模块积木的选择、键盘操作、组合顺序、自定义模块设计与保存、真实记录表单、模块库重启恢复，以及 AI 草案的预览与显式保存。该验收使用明确标记的测试模型响应，不产生真实模型费用；截图保存在 `artifacts/research-modules/`。

Electron 验收使用独立临时工作区和用户配置，验证搭建、数据导入、真实流程与重启恢复；截图和验收记录保存在 `artifacts/platforms/`。原版与学习版的桌面切换验收可运行 `node scripts/verify-experiences-electron.mjs`。
