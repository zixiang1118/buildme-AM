## 0. 给 Codex 的约束（先读）

1. **社区是独立的网站**，代码放在仓库根目录的 `community/` 下，有自己的 `package.json`，不参与 BuildMe 桌面端的构建和测试，也不能让桌面端现有的测试、typecheck、lint、build 失败。
2. **不做任何 AI 功能**。不调用任何大模型，不自动抓取内容，不自动生成摘要、标签或推荐。社区运行不产生按量计费的模型费用。
3. **不引入前端框架**。页面由服务端直接输出 HTML，交互用原生 JS 渐进增强；关掉 JS 也能浏览、登录、发帖和回复（编辑器退化为普通文本框）。
4. **不依赖在中国大陆打不开的资源**。不加载 Google Fonts、不用任何境外 CDN、不嵌入 YouTube 或 X 的播放器和脚本、不直接引用外站图片。字体、图标、脚本全部自己托管。唯一的例外是 GitHub 授权登录时跳转到 `github.com`。
5. **界面照样图实现**，颜色变量、圆角、字号直接复用样图 `<style>` 里的定义。中文界面，浅色和深色两套主题都要完成。
6. **本文档不要求你部署**。你交付代码、部署脚本和部署说明；真正上线由负责人另行执行。不要在代码或文档里写入任何真实的密钥、IP、域名，一律走环境变量。
7. 桌面端的改动只限 §10 列出的范围。不删除任何依赖，不改动 `release/`。
8. 有疑问或需要负责人决定的事，记入 `docs/community-open-questions.md`，按本文档的默认方案继续做，不要停下来等。
9. 每个里程碑（§12）完成后提交一次，进度写入 `docs/community-progress.md`。

## 1. 这是什么

BuildMe 的同学们交流 Agent 学习的论坛，同时是 BuildMe 的官网。

三件核心的事：

- **分享**：贴一个链接写几句话（推特的技术讲解、YouTube 视频、L 站的帖子、博客、GitHub 仓库），或者直接在这里写一篇长文。
- **讨论**：楼层式回复，可以用表情，可以对帖子和回复做表情回应。点赞多的帖子上首页。
- **作品墙**：展示大家用 Agent 做出来的东西，带封面图，标明是用哪个 harness 做的。

### 目标

- 分享一个链接不超过 30 秒：粘贴链接，标题自动填好，写两句话，点发布。
- 写长文体验不差：Markdown 编辑器、实时预览、粘贴或拖入图片、草稿自动保存。
- 在 BuildMe App 里点「社区」就能看和发，不用另开浏览器，不用重复登录。
- 在 App 里做完一次对比或解锁成就后，可以一键发到社区。
- 1000 名注册用户、峰值 100 人同时在线时流畅运行在一台 2 核 4G 的服务器上。

### 不做的事

- 不做 AI 摘要、AI 推荐、自动抓取内容。
- 不做私信、关注、粉丝、积分、等级、签到。
- 不做视频和附件上传（只支持图片）。
- 不做实时聊天室。

## 2. 技术方案

| 项 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js 22 LTS，TypeScript | 与主仓库一致 |
| Web 框架 | Hono（`@hono/node-server`） | 轻，自带 JSX 服务端渲染，无需前端构建 |
| 数据库 | SQLite（`better-sqlite3`，WAL 模式） | 1000 用户绰绰有余，单文件，备份简单 |
| 全文搜索 | SQLite FTS5，`trigram` 分词器 | 中文可用，不需要另起搜索服务 |
| Markdown | `markdown-it`（关闭 HTML）加服务端代码高亮 | 发布时渲染一次并缓存结果 |
| 图片处理 | `sharp` | 统一转 WebP、限制尺寸、去掉 EXIF |
| 图片存储 | 存储接口两种实现：本地磁盘（默认）、阿里云 OSS（配置后启用） | 开发和小规模用本地，上线后切 OSS |
| 密码哈希 | `node:crypto` 的 scrypt | 不引入额外原生依赖 |
| 会话 | 服务端会话表 + `HttpOnly` Cookie | 简单，可在后台强制下线 |
| 反向代理与 HTTPS | Caddy | 自动申请和续期证书 |
| 进程管理 | systemd | 开机自启，崩溃自动重启 |
| 测试 | vitest | 与主仓库一致 |

目录结构建议：

```
community/
  src/
    server.ts          入口
    db/                迁移、查询函数
    routes/            页面路由与表单处理
    views/             JSX 页面与组件
    lib/               链接解析、Markdown、图片、限流、排序、搜索、校验
  public/              样式、脚本、字体、图标
  scripts/             seed、备份、创建管理员
  deploy/              Caddyfile、systemd 单元、部署说明
  test/
```

配置全部来自环境变量，提供 `.env.example`：`PORT`、`DATA_DIR`、`SITE_URL`、`SESSION_SECRET`、`GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`GITHUB_MIN_ACCOUNT_AGE_DAYS`、`DOWNLOAD_MAC_URL`、`DOWNLOAD_WIN_URL`、`STORAGE_DRIVER`（`local` 或 `oss`）及 OSS 相关项。

## 3. 账号

两种注册方式，登录页并排显示两个入口。

### 3.1 GitHub 授权

- 点「用 GitHub 登录」，跳到 GitHub 授权页，只申请读取公开资料的权限（`read:user`）。授权后回到社区，第一次即自动创建账号并登录。
- 用户名默认取 GitHub 用户名；与已有用户重名时在后面加数字。头像取 GitHub 头像，**下载到本站存储后再显示**。
- 防广告：GitHub 账号注册不满 `GITHUB_MIN_ACCOUNT_AGE_DAYS`（默认 30）天的，不能直接注册，提示「你的 GitHub 账号太新，请使用邀请码注册」。
- 授权流程带 `state` 参数防伪造；回调里拿到的访问令牌只用来读一次资料，不保存。
- 未配置 `GITHUB_CLIENT_ID` 时，登录页不显示这个入口。

### 3.2 邀请码

- 填写用户名（2 到 16 个字符，中文、字母、数字、下划线，全站唯一，不区分大小写）、密码（至少 8 位）、邀请码。
- 邀请码由管理员在后台生成，可设置可用次数和过期时间。
- 忘记密码：由管理员在后台重置并生成一次性临时密码。登录页写明「忘记密码请联系管理员，或绑定 GitHub 后用 GitHub 登录」。

### 3.3 通用

- 邀请码账号可以在设置页绑定 GitHub，之后两种方式都能登录。一个 GitHub 账号只能绑定一个社区账号。
- 会话有效期 90 天，每次访问自动续期。
- 头像：GitHub 头像、自己上传的图片，或默认头像（用户名第一个字加由用户名哈希决定的底色）。
- 可以修改：头像、一句话简介（最多 60 字）、密码（邀请码账号）。用户名注册后 30 天内可以改一次。
- 未登录可以浏览和搜索全部内容；发帖、回复、点赞、表情回应、收藏、举报需要登录。

验收：

- **U-1** 用测试桩模拟 GitHub 授权成功，第一次自动创建账号并登录，第二次直接登录到同一个账号。
- **U-2** GitHub 账号创建时间不满设定天数时不创建账号，并显示改用邀请码的提示。
- **U-3** 回调请求的 `state` 缺失或不匹配时拒绝登录。数据库和日志里不出现 GitHub 访问令牌。
- **U-4** 用正确的邀请码能注册并自动登录；邀请码错误、过期或次数用尽时给出明确的中文提示，不创建账号。
- **U-5** 用户名重复（含大小写不同）时提示「这个用户名已被使用」。
- **U-6** 数据库里不存在明文密码；同一密码两次哈希结果不同。
- **U-7** 同一 IP 登录连续失败 5 次后，15 分钟内再次尝试直接被拒绝，并提示剩余等待时间。
- **U-8** 邀请码账号绑定 GitHub 后可用 GitHub 登录到同一账号；已被绑定的 GitHub 账号再次绑定时被拒绝。
- **U-9** 退出登录后，原 Cookie 不能再访问需要登录的接口。管理员重置密码后，旧会话全部失效，用户用临时密码登录后必须立即设置新密码。

## 4. 帖子

### 4.1 结构

| 字段 | 说明 |
|---|---|
| **标题** | 必填，4 到 80 字 |
| **板块** | 必选一个，见 4.2 |
| **正文** | Markdown，最多 50,000 字。分享链接时可以只写一两句；写文章时可以很长 |
| **链接** | 可选，只接受 `http` 和 `https`。有链接时帖子顶部显示链接卡片 |
| **标签** | 0 到 5 个，从管理员维护的列表里选；也可以申请新标签（管理员在后台批准后生效） |
| **图片** | 插在正文里，每帖最多 30 张 |
| **附带数据** | 作品帖见 §6，来自 App 的对比和成就见 §10 |

### 4.2 板块

初始板块（管理员可在后台增减、改名、排序）：

| 板块 | 用途 |
|---|---|
| 分享 | 转发好的链接：推文、视频、帖子、博客、仓库 |
| 文章 | 自己写的长文、学习笔记、教程 |
| 问答 | 提问和求助 |
| 作品 | 展示自己做的东西，同时出现在作品墙 |
| 闲聊 | 其他 |

每个板块有一个固定的颜色小圆点和一句说明，显示在帖子列表和发帖页。

### 4.3 两种发帖入口

**快速分享**（首页顶部的发帖框，照样图）：

- 点击后展开为：链接、标题、几句话、标签、发布。板块默认为「分享」。
- 粘贴链接后自动取标题填入（见 4.5），用户可以改。取不到时用户自己填。
- 发布成功后新帖出现在「最新」的最上面，页面不整体刷新。
- 旁边有「写长文」入口，进入完整编辑器。

**完整编辑器**（`/new`）：

- 左边编辑，右边实时预览；窄屏时用标签页切换。
- 工具栏：标题、加粗、斜体、引用、代码、代码块、链接、列表、图片、表情。常用快捷键可用（加粗、斜体、链接）。
- 图片：点按钮选择、拖入、或直接粘贴，上传中在光标处显示占位文字，完成后替换成图片语法。
- 表情：点按钮弹出选择面板（见 4.6）。
- 草稿：每 5 秒自动存到浏览器本地，重新打开时提示「恢复上次没发完的草稿」。同时提供「保存草稿」按钮存到服务器，在「我的草稿」里可以继续写，每人最多 20 篇。
- 提交前预览页与发布后的效果一致。

### 4.4 Markdown 与图片

- 支持：标题、加粗、斜体、删除线、引用、有序和无序列表、任务列表、表格、行内代码、代码块（带语言高亮和复制按钮）、链接、图片、分割线、`@用户名`。
- 不支持原始 HTML，输入的 HTML 标签原样显示为文字。
- 正文里的链接自动加 `rel="nofollow noopener ugc"`，在新标签页打开。
- **图片只能是本站上传的**。Markdown 里引用外站图片地址时，不显示图片，显示为一个普通链接。
- 上传限制：JPG、PNG、WebP、GIF；单张不超过 8MB；服务端校验真实格式，去掉 EXIF，最长边超过 2400 像素的缩小，静态图转 WebP，另生成一张宽 640 的缩略图。GIF 保持原格式但不超过 4MB。
- 正文里的图片懒加载，点击后在页面内放大查看。
- 长文自动生成目录（根据标题层级），在宽屏时显示在正文右侧。
- 渲染结果在发布和编辑时生成一次并存入数据库，浏览时不重复渲染。

### 4.5 链接识别（不使用 AI）

粘贴链接时服务器做一次轻量解析，只取标题和缩略图地址，**不保存对方的正文，不做任何总结**。

| 域名 | 来源标记 | 标题获取方式 |
|---|---|---|
| `x.com`、`twitter.com` | X | `publish.twitter.com/oembed`，取作者名加正文前 60 字 |
| `youtube.com`、`youtu.be` | YouTube | `youtube.com/oembed`，同时取缩略图 |
| `bilibili.com`、`b23.tv` | B 站 | 页面的 `og:title` 和 `og:image` |
| `linux.do` | L 站 | 页面的 `og:title` |
| `github.com` | GitHub | 页面的 `og:title` |
| `mp.weixin.qq.com` | 公众号 | 页面的 `og:title` |
| 其他 | 显示域名 | 页面的 `og:title`，没有则取 `<title>` |

- 解析请求超时 4 秒，响应体最多读 512KB，最多跟随 3 次跳转。
- **防 SSRF**：解析前先做 DNS 解析，目标是内网、回环、链路本地地址或非 80/443 端口时拒绝；每一次跳转后重新检查。
- 缩略图下载到本站存储并按 4.4 的规则处理。下载失败就不显示缩略图。
- 同一个链接的解析结果缓存 24 小时。解析接口需要登录，每个用户每分钟最多 10 次。
- 同一个链接 7 天内已有人发过时，发布前提示「这个链接 3 天前 @某某 分享过」并给出原帖入口，用户可以选择继续发布。

链接卡片指向 `/go/<帖子ID>`，服务器记录一次点击后跳转到真实地址。同一用户或同一 IP 对同一帖子 1 小时内只计 1 次。

### 4.6 表情

- 正文和回复里可以直接输入或从面板选择表情。表情用系统自带的 Unicode 表情显示，不加载任何表情图片包。
- 表情面板：分「常用」（本人最近用过的 16 个，存在浏览器本地）和几个分类，带搜索（按中文名称）。表情数据打包在站内脚本里。
- 输入 `:` 加关键词时弹出联想（如 `:笑`），回车选中。

### 4.7 编辑与删除

- 自己的帖子随时可以编辑。编辑过的帖子显示「编辑于 某时间」。发布 24 小时后再改标题需要管理员权限。
- 保留最近 10 次编辑的历史版本，管理员可以查看。
- 删除是软删除，回复一并隐藏。

验收：

- **P-1** 粘贴一个 YouTube 链接，2 秒内标题自动填入；发布后卡片显示缩略图、标题和来源标记，缩略图地址是本站域名。
- **P-2** 链接解析失败或超时时，用户仍然可以手填标题并发布成功。
- **P-3** 标题为空或超长、未选板块、正文超过 50,000 字、链接不是 http/https 时，发布被拒绝并在对应位置显示中文原因，已输入的内容不丢失。
- **P-4** 一篇含标题、表格、代码块、任务列表、图片、表情的 20,000 字长文能正常发布，详情页显示与预览一致，并生成目录。
- **P-5** 正文里的 `<script>`、`<img onerror>`、`javascript:` 链接都不会被执行，显示为文字或被去掉。
- **P-6** Markdown 引用外站图片时页面不向外站发出图片请求。
- **P-7** 上传一张带 GPS 信息的 6MB 照片，保存后的文件不含 EXIF、格式为 WebP、最长边不超过 2400；上传一个改了扩展名的非图片文件被拒绝。
- **P-8** 把链接指向 `http://127.0.0.1`、`http://169.254.169.254`、`http://10.0.0.1` 或一个会跳转到这些地址的外网地址，解析接口返回失败且服务器没有向这些地址发出请求（用测试桩验证）。
- **P-9** 在编辑器里写到一半关闭页面，重新打开 `/new` 时提示恢复草稿，恢复后内容完整。
- **P-10** 编辑帖子后显示「编辑于」，历史版本里有修改前的内容。
- **P-11** 删除自己的帖子后，它从所有列表和搜索结果消失，直接访问显示「这条帖子已删除」。
- **P-12** 关闭浏览器 JS 后，仍能完成登录、发帖（纯文本框写 Markdown）、回复、点赞。

## 5. 回复、点赞与表情回应

### 5.1 回复（楼层式，参考 linux.do）

- 帖子下方按时间顺序排列回复，每条有楼层号（`#1`、`#2`…）。
- 回复支持 Markdown、表情和图片，最多 10,000 字。
- 可以「回复」某一楼：新回复顶部显示「回复 #3 @某某」，点击后页面滚到那一楼并高亮。被回复的那一楼下方显示「2 条回复」，点开可就地展开查看。
- 选中某一楼的一段文字时，出现「引用」按钮，点击后把这段文字作为引用块插入回复框。
- 输入 `@` 时弹出用户名联想（本帖参与者优先）。
- 帖子作者的回复带「楼主」标记。
- 自己的回复可以编辑和删除。
- 回复超过 30 条时分页加载（每次 30 条），右侧显示楼层进度条（「12 / 86」），可以拖动跳转。
- 每一楼有固定地址 `/p/<帖子ID>#<楼层号>`，可以复制分享。

### 5.2 点赞

- 帖子有「点赞」按钮（样图里卡片左侧的向上箭头和数字）。每人每帖一次，可以取消。不能给自己的帖子点赞。
- 点赞数是上首页的主要依据（见 7.1）。

### 5.3 表情回应

- 帖子和每一条回复下方都可以加表情回应。固定 8 个：👍 ❤️ 😂 🎉 🤔 👀 🚀 🙏。
- 已有的回应显示为一排小胶囊（表情加人数），点一下就加入或取消；鼠标停留显示是谁点的（最多显示 10 个名字）。
- 每人对同一内容可以点多种表情，每种一次。
- 对回复来说，表情回应就是点赞，不另设点赞按钮。

### 5.4 收藏

帖子可以收藏，在「我的收藏」里查看，只有自己可见。

验收：

- **R-1** 回复某一楼后，新回复显示回复对象，点击能跳到并高亮那一楼；被回复的楼显示回复数并可就地展开。
- **R-2** 选中文字点「引用」，回复框里出现正确的引用块和出处。
- **R-3** 一个有 200 条回复的帖子：首次只加载 30 条，滚动或拖动楼层进度条能到达任意楼层；直接打开 `…#150` 时定位到第 150 楼。
- **R-4** 点赞、取消点赞即时反映在页面上，刷新后保持；重复请求不会让同一人计数超过 1；给自己的帖子点赞被拒绝。
- **R-5** 表情回应可以添加和取消，人数正确；同一人对同一内容的同一表情只计一次；提交 8 个固定表情以外的值被拒绝。
- **R-6** `@某某` 渲染为指向该用户主页的链接；不存在的用户名保持为普通文字。

## 6. 作品墙

作品墙是「作品」板块的另一种展示方式：带封面图的卡片网格，让人一眼看到大家做了什么。

### 6.1 发布作品

入口：作品墙页面的「发布作品」按钮，或发帖时选择「作品」板块。表单比普通帖子多几项：

| 字段 | 说明 |
|---|---|
| 作品名 | 即帖子标题，4 到 40 字 |
| 一句话介绍 | 必填，最多 60 字 |
| **封面图** | 必填，一张。上传后裁成 16:10，提供裁剪框 |
| 体验地址 | 可选，作品的在线地址 |
| 源码地址 | 可选 |
| **用什么做的** | 必选至少一项，可多选：BuildMe、Claude Code、Codex、Cursor、其他（可填名称，最多 20 字）。选项列表由管理员维护 |
| 详细介绍 | 即帖子正文，Markdown，可以放更多截图，讲怎么做的、遇到了什么问题 |

### 6.2 作品墙页面 `/works`

- 卡片网格：宽屏每行 4 张（App 内嵌时同样 4 张），中屏 2 到 3 张，手机 1 张。
- 每张卡片：封面图、作品名、一句话介绍、作者头像和名字、「用什么做的」小标记、点赞数、回复数。照样图。

- 筛选：按「用什么做的」筛选（一排可点的小标记）。这是有意设计的：同学们可以直接看到不同 harness 做出来的东西。
- **精选**：管理员可以把作品标为精选，精选作品在作品墙顶部以更大的横向卡片显示（宽屏一行 2 个，最多 4 个），带「精选」标记。
- 点卡片进入作品详情页：就是帖子详情页，顶部多一块作品信息区（大封面、体验和源码按钮、用什么做的），下面是详细介绍和回复。

### 6.3 在别处露出

- **首页**：信息流顶部有一条「作品墙」横条，显示最近 14 天里点赞最多的 4 个作品（不足 4 个时用最新的补），右侧「看全部」进入作品墙。照样图。
- **顶部导航**：「作品墙」是与热门、最新并列的一级入口。
- **用户主页**：「作品」标签页，以卡片网格显示这个人的作品。
- **下载页**：显示 3 个精选作品，作为「大家用 BuildMe 做了什么」。
- **BuildMe App**：社区入口进去后同样可见；见 §10。

验收：

- **W-1** 发布作品时没有封面图、没有一句话介绍或没有选「用什么做的」，被拒绝并提示原因。
- **W-2** 上传任意比例的封面图，裁剪后保存为 16:10；卡片上的封面不变形。
- **W-3** 作品同时出现在作品墙和「作品」板块的帖子列表里，两处的点赞数和回复数一致。
- **W-4** 作品墙的两种排序和时间范围显示的顺序正确；按「用什么做的」筛选后只显示包含该项的作品。

- **W-6** 首页的作品墙横条显示 4 个作品，符合「最近 14 天点赞最多，不足用最新补」的规则；一个作品都没有时横条显示「还没有作品，来发第一个」。

## 7. 浏览、搜索与通知

### 7.1 首页

布局照样图：左边是信息流，右边是侧栏（宽 300）。

顶部一级入口：**热门**（默认）、**最新**、**精华**、**作品墙**。下面一排板块筛选（全部、分享、文章、问答、作品、闲聊）。

- **热门**：点赞多、讨论多的新帖。热度 = `(点赞数 × 2 + 表情回应数 + 回复数 × 2 + 1) / (发布后小时数 + 2)^1.5`，只算最近 14 天的帖子，每 5 分钟重新计算并缓存。**这就是「点赞量高的上首页」**。
- **最新**：按最后活动时间倒序（有新回复的帖子会浮上来，同 linux.do）。可切换为按发布时间。
- **精华**：管理员标记为精华的帖子，加上按点赞数排的榜单（本周、本月、全部）。

每页 30 条，滚到底部自动加载更多（没有 JS 时是下一页链接）。置顶帖（管理员设置，最多 3 条，可限定在某个板块内）排在最上面，带「置顶」标记。

登录用户回到首页时，上次访问之后的新帖和有新回复的帖子，标题旁有一个小圆点。

### 7.2 帖子卡片

照样图。包含：

- 左侧点赞区：向上箭头和数字，已点赞时用品牌色底。
- 第一行：作者头像、用户名、相对时间、板块标记。
- **标题**（最醒目，点击进详情）。
- 正文摘要：取正文开头的纯文字，最多 2 行。这是直接截取，不是 AI 摘要。
- 链接卡片（如果有）：来源标记、链接标题、域名；视频类带缩略图。长文帖如果正文里有图，显示第一张图的缩略图。
- 最后一行：表情回应胶囊、回复数、浏览数、标签。

### 7.3 侧栏

- **本周大家在看**：最近 7 天浏览加链接点击最多的 5 条帖子。每 10 分钟更新。
- **标签**：最常用的 12 个标签，「全部标签」进入标签页。
- **社区数据**：成员数、帖子数、今日新帖数。
- **分享你的发现**：说明文字（见样图）；在 App 外的浏览器里显示为「下载 BuildMe」入口。

### 7.4 搜索

顶部导航有搜索框，快捷键 `/` 聚焦。

- 搜索范围：帖子标题、正文、标签、作品的一句话介绍；可切换到「回复」和「用户」。
- 输入时下拉显示最多 6 条即时结果（标题匹配优先），回车进入完整结果页 `/search?q=`。
- 结果页：关键词在标题和摘要里高亮；可以按板块、标签、作者、时间范围筛选；排序可选「相关度」（默认，标题命中的权重高于正文）和「最新」。
- 支持的写法：`@用户名` 只看某人的，`#标签` 只看某标签，加引号精确匹配。结果页上方有这些写法的简短说明。
- 实现：FTS5 的 `trigram` 分词器建索引；查询词不足 3 个字符时退回 `LIKE` 匹配。发帖、编辑、删除时同步更新索引。
- 已删除、被隐藏、被封禁用户的内容不出现在结果里。
- 未登录也能搜索；每个 IP 每分钟最多 30 次。

### 7.5 通知

顶部导航有通知图标，有未读时显示数字。

触发通知的事：有人回复了你的帖子、有人回复了你的回复、有人 `@` 了你、你的帖子被设为精华或精选、你的内容被管理员处理。点赞和表情回应合并通知（「某某等 5 人赞了你的帖子《…》」），同一帖子 1 小时内只产生一条。

通知页列出最近 200 条，点击跳到对应位置并标为已读，可以「全部标为已读」。只做站内通知，不发邮件。

### 7.6 其他页面

- **用户主页** `/u/<用户名>`：头像、用户名、简介、加入时间、发帖数、获赞数；标签页：帖子、作品、回复；自己的主页多「收藏」和「草稿」。
- **标签页** `/tags` 和 `/t/<标签>`；**板块页** `/c/<板块>`。
- **下载页** `/download`：BuildMe 的一句话介绍、macOS 和 Windows 下载按钮（地址来自环境变量）、当前版本号、界面截图位、3 个精选作品。未配置下载地址时按钮显示「即将开放」并禁用。
- **关于与规则** `/about`：社区规则（文字由负责人提供，先放占位内容）和联系方式。
- **RSS**：`/feed.xml`（最新）和每个板块、每个标签各自的订阅地址。

### 7.7 独立网站与嵌入 App 的区别

| | 浏览器直接访问 | 在 BuildMe App 里 |
|---|---|---|
| 顶部导航 | Logo、热门/最新/精华/作品墙、搜索、通知、下载 BuildMe、登录或头像 | 隐藏 Logo 和下载按钮，其余保留（样图所示） |
| 主题 | 跟随系统，可手动切换 | 跟随 App 的主题 |
| 外部链接 | 新标签页打开 | 用系统浏览器打开 |

App 通过在地址上加 `?embed=1&theme=dark|light` 进入嵌入模式；服务器把这两个值写入 Cookie，后续页面保持。

### 7.8 手机

宽度小于 760 像素时：侧栏移到信息流下方，顶部导航收成一行加一个菜单，帖子卡片的点赞区移到底部操作行，编辑器的编辑和预览改为标签页切换。页面不出现横向滚动。

验收：

- **B-1** 首页默认是热门；用测试数据验证热度公式的排序，点赞更多的同期帖子排在前面。
- **B-2** 「最新」按最后活动时间排序：给一个旧帖加一条回复后，它回到最上面。
- **B-3** 连续加载更多不出现重复帖子，也不漏帖（期间有新帖发布的情况下）。
- **B-4** 板块筛选、标签页、精华榜的时间范围切换都显示正确的内容。
- **B-5** 帖子卡片的摘要是正文开头的纯文字，不含 Markdown 符号，不超过 2 行。
- **B-6** 搜索：搜「harness」能找到标题或正文含这个词的帖子，标题命中的排在正文命中的前面；搜两个字的中文词有结果；搜 `@某某 上下文` 只返回该用户的帖子；关键词在结果里高亮。
- **B-7** 编辑帖子后，用新内容里的词能搜到、用已删掉的词搜不到；删除的帖子搜不到。
- **B-8** 即时结果在停止输入 200 毫秒后出现，连续输入时不会为每个字符都发请求。
- **B-9** 别人回复我的帖子、回复我的回复、`@` 我，我都收到通知，点击跳到对应楼层；5 个人在 1 小时内给同一帖点赞只产生 1 条通知；自己对自己的操作不产生通知。
- **B-10** 在 390 像素宽的视口下，首页、详情页、编辑器、登录、作品墙、搜索结果都没有横向滚动条，所有按钮可以点到。
- **B-11** 浅色和深色主题下，所有文字与背景的对比度不低于 4.5:1，代码高亮在两种主题下都清晰。
- **B-12** 带 `?embed=1` 访问时不显示 Logo 和下载按钮；之后在站内跳转，嵌入模式保持。
- **B-13** `/feed.xml` 是合法的 RSS，包含最新 30 条帖子的标题、链接、作者和时间。

## 8. 防广告与内容管理

社区对公网开放，这一部分不能省。

### 8.1 新账号限制

注册不满 24 小时或发帖回复合计不足 3 条的账号视为新账号：

- 发帖、回复的频率限制减半。
- 每条内容最多 2 个外部链接、2 张图片。
- 第一条帖子进入待审队列，管理员通过后才公开（作者自己能看到，并看到「审核中」提示）。通过一次后不再审核。

### 8.2 限流

| 动作 | 限制 |
|---|---|
| 注册 | 每 IP 每小时 5 次 |
| 发帖 | 每用户每小时 10 条，两条之间至少间隔 30 秒 |
| 回复 | 每用户每分钟 6 条 |
| 上传图片 | 每用户每小时 60 张，每天 200 张 |
| 点赞、表情回应、收藏 | 每用户每分钟 60 次 |
| 搜索 | 每 IP 每分钟 30 次 |
| 举报 | 每用户每天 20 次 |

超限时返回 429 和中文提示，写明多久之后可以再试。

### 8.3 重复内容

同一用户 10 分钟内提交与自己上一条内容相似度很高的帖子或回复（去掉空白后文本相同，或只有数字和标点不同）时拒绝。同一个外部域名被同一个新账号在 24 小时内发超过 3 次时，后续内容进待审队列。

### 8.4 举报

帖子和回复都有「举报」入口，选择原因（广告、与主题无关、不友善、违法违规、其他）并可填写说明。同一内容被 3 个不同用户举报后自动隐藏，等待管理员处理。

### 8.5 屏蔽词

管理员维护屏蔽词列表，分两级：**拒绝**（命中则不能提交，提示「内容包含不允许的词语」，不指出具体的词）和**待审**（可以提交，但进待审队列）。检查范围：标题、正文、回复、用户名、简介、链接标题。

### 8.6 管理后台 `/admin`

仅管理员可进。第一个管理员用 `scripts/create-admin.ts` 在命令行创建。另有「版主」角色：能处理待审和举报、删帖、设精华，不能管理用户、邀请码和站点设置。

- **待处理**：待审内容和被举报内容，可以通过、恢复显示或删除，可以同时封禁作者。
- **帖子**：搜索、删除、置顶、设为精华、移动板块、查看编辑历史。
- **作品**：设为精选或取消。
- **用户**：搜索、封禁或解封（封禁后不能登录，其帖子和回复全部隐藏）、禁言若干天（能登录不能发言）、重置密码、设置角色。
- **邀请码**：生成、查看使用情况、作废。
- **板块、标签、「用什么做的」选项**：增加、改名、排序、停用；处理新标签申请。
- **屏蔽词**：增删。
- **数据**：注册用户数、今日和 7 日活跃用户数、今日发帖和回复数、存储占用，各一个数字。

所有管理操作写入操作日志表（谁、什么时候、对什么、做了什么）。

验收：

- **M-1** 新账号的第一条帖子不出现在公开列表里，作者自己可见并看到「审核中」；管理员通过后公开，该用户之后的帖子直接公开。
- **M-2** 新账号发含 3 个外部链接的内容被拒绝，并说明新账号的限制。
- **M-3** 每一项限流都有测试：达到上限后下一次请求返回 429，等待时间过后恢复。
- **M-4** 连续提交两条相同内容，第二条被拒绝。
- **M-5** 第 3 个不同用户举报后，内容立即从所有列表、详情页和搜索隐藏；管理员「恢复显示」后重新出现，举报计数清零。
- **M-6** 命中「拒绝」级屏蔽词不能提交；命中「待审」级的进入待审队列。
- **M-7** 非管理员访问 `/admin` 下任何地址返回 404。版主访问用户管理和邀请码页面返回 404。
- **M-8** 被封禁的用户：现有会话立即失效，登录时提示「账号已被停用」，其内容对其他人不可见。被禁言的用户能浏览，发言时提示禁言到期时间。
- **M-9** 所有会修改数据的表单和接口都校验 CSRF 令牌，缺少或错误时返回 403。
- **M-10** 每次管理操作在操作日志里有对应记录。

## 9. 安全与性能

- 所有页面带 `Content-Security-Policy`：脚本、样式、图片、字体只允许本站来源（启用 OSS 时加上 OSS 的图片域名），禁止内联脚本。
- Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`。
- 所有用户输入在输出时转义；Markdown 渲染结果再过一遍白名单过滤；链接的 `href` 只允许 `http`、`https` 和站内相对地址。
- 所有数据库查询使用参数绑定。
- 上传的图片存放路径由服务器生成（随机名），不使用用户提供的文件名；图片由不执行任何脚本的静态路径提供，带 `X-Content-Type-Options: nosniff`。
- 静态资源文件名带内容哈希，缓存一年；HTML 不缓存。开启 gzip 或 brotli。
- 首页的 HTML 加全部 CSS、JS、字体合计不超过 300KB（压缩后，不含帖子里的图片）。编辑器和表情面板的脚本只在需要时加载。
- 字体：界面用系统中文字体；拉丁字母和数字用的 Schibsted Grotesk、JetBrains Mono 只打包实际用到的字重，woff2 格式，放在 `public/fonts/`。
- 提供 `/healthz`，返回数据库是否可读写。
- 日志输出到标准输出，一行一条 JSON，不记录密码、Cookie、访问令牌和完整 IP（IP 只保留前三段）。

验收：

- **S-1** 用 seed 脚本生成 1000 个用户、5 万条帖子（其中 500 篇万字长文、2000 个作品）、20 万条回复后，对首页热门、最新、作品墙、一个 200 楼的详情页、一次搜索各压测 30 秒（并发 50），95 分位响应时间：列表和详情不超过 150 毫秒，搜索不超过 300 毫秒，无 5xx。结果写入进度文档。
- **S-2** 页面里除用户点击的外部链接外，没有任何指向本站（及配置的图片域名）以外的资源请求。用测试扫描渲染出的 HTML 验证。
- **S-3** 日志里搜不到任何密码、会话 ID、访问令牌或完整 IP。

## 10. 与 BuildMe App 的集成

这一节是对桌面端的改动，范围只限于此。

### 10.1 嵌入

- 侧栏增加「社区」入口（样图里已有）。点击后，主区域显示一个加载社区网址的内嵌网页视图（Electron 的 `WebContentsView` 或 `<webview>`，使用独立的持久化 session 分区 `persist:community`，登录状态在 App 重启后保留）。
- 社区网址来自 App 配置，默认值留空；为空时「社区」入口显示「即将开放」。
- 内嵌视图**不注入** preload，不暴露 `window.personalAgent`，不能访问 App 的任何能力。禁用 Node 集成，开启沙箱和上下文隔离。
- 内嵌视图里只允许浏览社区自己的域名，以及 GitHub 授权流程需要的 `github.com` 页面（仅当导航是从社区的 GitHub 登录入口发起时放行，回到社区域名后恢复限制）。其他域名的导航和新窗口一律拦截，改用系统浏览器打开。
- App 切换主题时，重新带上 `theme` 参数通知社区页面切换。
- 断网或社区打不开时，显示 App 自己的提示页：说明原因和「重试」按钮，不显示浏览器默认错误页。
- 加载时在标题栏下方显示一条细进度条。
- 侧栏「社区」入口上显示未读通知数（内嵌视图加载后由社区页面通过页面标题上的数字前缀传出，App 读取标题得到；不建立其他通信通道）。

### 10.2 一键分享

App 里三个地方有「分享到社区」按钮：对比完成后的差别摘要栏、成就解锁提示、成就页。

点击后 App 切到社区视图并打开 `/new?type=compare`（或 `achievement`），把数据放在地址的 `#` 片段里（base64url 编码的 JSON，片段不会进服务器日志）。页面脚本读出数据，显示预览卡片；标题预填（如「同一个任务，我的 Agent 和完全体差了 3 倍 tokens」），板块预选「分享」，用户写几句话后发布。

**对比数据（只有数字和名称，不含任何对话内容、文件内容、文件路径）：**

```json
{
  "v": 1,
  "model": "deepseek-chat",
  "pi":  { "capabilities": 4, "llmCalls": 6,  "toolCalls": 4,  "tokens": 31200, "seconds": 48 },
  "dsh": { "llmCalls": 17, "toolCalls": 19, "tokens": 94600, "seconds": 41 },
  "dshOnly": ["子 Agent", "联网搜索"]
}
```

**成就数据：**

```json
{ "v": 1, "id": "parallel-tools", "name": "左右开弓", "unlocked": 11, "total": 30 }
```

服务器对这两种数据做严格校验：字段类型、数值范围（非负、不超过合理上限）、字符串长度、`dshOnly` 最多 8 项且每项不超过 12 字。校验不通过拒绝发布。数据是用户自己提交的，卡片上不标注「已验证」之类的字样。

卡片样式：对比卡是两条横向比例条加数字（照样图），成就卡显示一块积木、成就名和「11/30」。

验收：

- **I-1** 在 App 里点「社区」，1 秒内出现进度条；页面加载后不显示网站自己的 Logo 和下载按钮，主题与 App 一致。
- **I-2** 在 App 里用 GitHub 授权登录能走完流程并回到社区；用邀请码账号登录同样可以。完全退出并重新打开 App，仍然是登录状态。
- **I-3** 在内嵌视图的开发者工具里，`window.personalAgent` 为 `undefined`，`require` 不可用。
- **I-4** 点击帖子里的外部链接，系统浏览器打开真实地址，内嵌视图停留在社区。未经 GitHub 登录入口直接导航到 `github.com` 时同样交给系统浏览器。
- **I-5** 断开网络后点「社区」，显示 App 自己的提示页；恢复网络后点「重试」能正常加载。
- **I-6** 完成一次对比后点「分享到社区」，社区的发帖页出现对比预览卡，数字与 App 里的差别摘要一致；发布后在信息流里显示为对比卡片。
- **I-7** 检查分享时生成的地址：不包含提问内容、回答内容、文件名或路径。
- **I-8** 手动构造一份数值为负数或带超长字符串的对比数据提交，服务器拒绝。
- **I-9** 社区网址配置为空时，「社区」入口显示「即将开放」，点击没有反应，App 其他功能不受影响。
- **I-10** 有未读通知时，App 侧栏的「社区」入口显示数字；在社区里读完后数字消失。

## 11. 部署与运维（交付脚本和说明，不执行）

在 `community/deploy/` 下交付：

- `README.md`：在一台全新的 Ubuntu 24.04 服务器上从零部署到可访问的完整步骤，每一步给出可以直接复制的命令。包含「如何创建 GitHub OAuth App 并填写回调地址」的说明。
- `Caddyfile`：域名来自变量，自动 HTTPS，反向代理到本机端口，静态资源和本地存储的图片直接由 Caddy 提供；请求体上限 10MB。
- `buildme-community.service`：systemd 单元，以专用的非 root 用户运行。
- `deploy.sh`：本地构建、把产物同步到服务器、执行数据库迁移、重启服务、检查 `/healthz`；健康检查失败时自动回退到上一个版本。
- `backup.sh`：用 SQLite 的在线备份方式导出数据库，连同本地图片目录打包，上传到对象存储（地址和凭证来自环境变量），本地保留最近 7 份。附 cron 配置示例（每天凌晨 4 点）。
- `restore.md`：从备份恢复的步骤。
- `migrate-images-to-oss.ts`：把本地图片迁到 OSS 并更新数据库里的地址。

数据库迁移：`community/src/db/migrations/` 下按序号排列的 SQL 文件，启动时自动执行未执行过的迁移。

孤儿图片清理：上传后 24 小时内没有被任何已发布内容或草稿引用的图片，由每日任务删除。

验收：

- **D-1** 在一个干净的 Ubuntu 24.04 容器里，严格照 `deploy/README.md` 操作（HTTPS 和 GitHub 部分除外），服务能启动，`/healthz` 返回正常。
- **D-2** 运行备份脚本得到一个包；在另一个空目录里照 `restore.md` 恢复后，帖子、用户、图片都在。
- **D-3** 对已有数据的数据库重复执行迁移不报错、不丢数据。
- **D-4** 上传后未被引用的图片在清理任务运行后被删除；被草稿或帖子引用的不受影响。

## 13. 测试要求

- 每条验收项至少对应一个自动化测试，测试名里带验收编号（如 `P-8 拒绝内网地址`）。无法自动化的（需要真实窗口的 I-1、I-2、I-5 等）写入人工验收清单。
- 链接识别和 GitHub 授权的测试使用本地测试桩服务器，不访问真实外网。
- 测试使用内存数据库或临时目录，互不影响，可以并行。
- `community/` 下 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build` 全部通过。
- 主仓库原有的全部检查继续通过。

### 人工验收清单（负责人照着点一遍）

1. 浏览器打开首页，不登录能看到热门帖子列表和作品墙横条，各个入口可以切换。
2. 用 GitHub 授权登录；退出后用邀请码再注册一个账号。
3. 快速分享：粘贴一个 YouTube 链接，标题自动出现；写两句话，发布；新帖带缩略图出现在「最新」最上面。
4. 写长文：进入编辑器，写标题、几段带代码块和表格的正文，粘贴一张截图，插入几个表情，预览后发布；详情页有目录。
5. 写到一半关掉页面再回来，草稿能恢复。
6. 回复一条帖子；再回复某一楼；选中一段文字引用；`@` 另一个账号。
7. 给帖子点赞，给一条回复加表情回应；另一个账号收到通知并能跳到对应楼层。
8. 发布一个作品：上传封面并裁剪，选「用什么做的」；在作品墙看到它，按 harness 筛选能找到。
9. 搜索一个刚发的帖子里的词，结果里关键词高亮；试一次 `@用户名` 搜索。
10. 把窗口缩到手机宽度，首页、详情页、编辑器、作品墙布局正常。
11. 切换深色主题，所有页面看起来正常。
12. 用新注册的账号发第一条帖子，看到「审核中」；用管理员账号在后台通过它。
13. 用两个以上账号举报一条帖子至自动隐藏；管理员在后台处理。
14. 管理员把一个作品设为精选、一条帖子设为精华，对应位置出现。
15. 打开 BuildMe App，点「社区」，看到同样的内容；重启 App 后不需要重新登录。
16. 在 App 里做一次对比，点「分享到社区」，写一句话发布，信息流里出现对比卡片。
17. 断网后点「社区」，看到提示页；联网后点重试恢复。
