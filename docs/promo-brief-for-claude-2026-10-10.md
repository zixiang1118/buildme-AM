**产品全功能清单 · 社区 · 未来概念 · 可直接交给 Claude 的商业片 brief**
整理日期：2026 年 10 月 10 日。基于当前仓库代码、产品文档与已有本机验收记录。

本文可以独立交给 Claude，无需附带聊天记录。前半部分提供产品事实和创意素材，后半部分给出影片方向与制作任务。功能清单用于理解产品；主片需要选择最有感染力的几个瞬间。

## 01｜先记住这一句话

> **BuildMe。把 AI 的能力，变成你的能力。**

BuildMe 是一个面向学生和创作者的 Agent 桌面应用，也是一个让作品与发现相遇的社区。

你可以用它完成真实任务：理解项目、修改代码、读取资料、制作作品。你也可以打开 X 光，查看一次回答背后的模型请求、工具调用、提示词、上下文和 Token 用量；亲手给 Agent 增加能力；让不同引擎、模型或读取策略面对同一个任务；最后把作品、对比结果与探索足迹分享给同学。

它希望带来的变化是：**做出作品，积累判断，逐渐掌握自己的创造方式。**

产品的体验顺序：**动手创造 → 看见过程 → 调整能力 → 对照验证 → 分享发现 → 开始下一次创造。**

学习自然发生在这个循环里。学生接触到的知识包括 Agent、harness、提示词、工具调用、Skill、上下文工程、压缩、缓存、子 Agent、工作流、权限，以及如何更有效地使用 Claude Code、Codex 等工具进行 Vibe Coding。

### 适合商业片的六个核心卖点

| 核心卖点 | 面向观众的表达 | 最有力量的画面 |
|---|---|---|

| X 光模式 | **看见每一步。** | 平静的回答界面展开为真实调用时间线，镜头停在关键事件 |

| 双路对比 | **同一个问题，看见不同的可能。** | 相同任务分成两路，各自展开执行过程，最终对照作品和文件变化 |
| 发现卡与 Token 账单 | **每一次运行，都有值得发现的细节。** | 一张小卡定位到 Skill 加载；一次高输入请求展开成上下文来源 |
| 社区与作品墙 | **让你的发现，成为别人的起点。** | 一个作品进入作品墙，同学打开、讨论，镜头延展为更多作品 |

## 03｜现有桌面产品：完整功能清单

### A. 一个真正能动手的 Agent 工作台【现有】

**宣传表达：从一句话开始，让想法长出形状。**

| 功能 | 用户实际可以做什么 |
|---|---|
| 自然语言任务 | 输入自己的需求，使用真实模型推进代码、资料和项目任务 |
| 流式回答 | 在生成过程中逐步看到回答与工具执行状态 |
| 本地工作区 | 选择项目目录，让 Agent 围绕真实文件工作 |
| 文件读取、写入与编辑 | 阅读代码与文本，创建文件，修改已有内容 |
| 命令执行 | 通过命令完成项目检查、开发和其他任务，受所选权限及运行环境约束 |
| 连续对话 | 在同一会话继续补充要求、追问与迭代 |
| 历史会话 | 查看近期会话、刷新列表、重新打开历史内容 |
| 新建会话 | 为新的工作建立独立对话 |
| 停止执行 | 主动中止正在运行的任务 |
| 两种运行模式 | 在统一桌面界面选择 Build 轻量模式或 DSH 全量版 |
| 实际产物 | 结果可以落在真实项目文件中，继续由用户运行、编辑与使用 |

适合拍摄的演示任务：为一个本地项目增加交互、整理一组研究资料、制作一个可运行的小工具。最终选用经过实际运行与检查的作品画面，避免把模型口头宣告当作完成证据。

### B. 自由连接模型【现有／连接需配置】

**宣传表达：选择你的模型，形成自己的工作方式。**

- 保存、命名和切换多组模型连接。
- 配置服务商、模型 ID、API 地址及 API Key。
- 对接官方服务、兼容接口中转站，以及用户已经启动的本地模型服务。
- 设置界面包含 DeepSeek、OpenAI、Anthropic、Google Gemini、OpenRouter、Groq、Mistral、xAI、通义千问、豆包／火山方舟、Kimi、GLM、MiniMax、硅基流动、Ollama、LM Studio 和 OpenAI 兼容连接入口。
- 支持自定义模型 ID；可用性取决于服务商、接口协议和用户账户权限。
- 本地保存连接设置；密钥使用应用的系统安全存储能力保护。

制作提示：模型选择可以一闪而过。重点是自主选择与对照体验，不把支持列表拍成品牌 Logo 墙，也不宣称每个服务商都完成了实机验证。

### C. 我的 Agent：基础能力 + 九项扩展【现有】

**宣传表达：它的每一次成长，都有你的选择。**

基础能力始终开启：读取、写入、编辑、命令执行与工作区信息。除此之外，用户可以打开以下 **9 项扩展能力**：

| 扩展能力 | 实际作用 | 商业片短句 |
|---|---|---|
| 读文档 | 读取 PDF、Word、HTML 和文本等内容；PDF 可按页读取 | 让资料进入工作 |
| 搜索工作区 | 在项目中定位相关文件和内容 | 从更多信息中，找到需要的部分 |
| 读网页 | 获取网页正文，为任务补充外部信息 | 把网页带进思考的上下文 |
| 任务清单 | 创建和更新待办，呈现任务推进情况 | 让进展清晰可见 |
| 计划 | 组织方案与行动步骤 | 先看清方向，再开始行动 |
| Skill | 查看可用技能、加载操作指南，按任务引入专业流程 | 给它一套更好的做事方法 |
| 上下文压缩 | 在长对话中整理上下文，支持任务继续推进 | 让长任务继续向前 |
| 子 Agent | 将部分工作交给子任务，再汇总结果 | 让一个任务，展开多条思路 |
| 工作流 | 按阶段组织子任务与执行步骤 | 让能力开始协作 |

配套体验：

- 初次使用可从基础配置开始，也可选择全部扩展能力。
- 每张能力卡解释「是什么」「打开前后有什么区别」，并说明其与 Claude Code、Codex 相关概念的对应关系。
- 「试试看」把一个可用示例放入输入框，由用户决定发送。
- 能力面板展示实际使用次数；界面显示当前能力状态。
- 工作流自动关联所需的子 Agent 能力，相关依赖联动更新。
- 配置修改从下一回合生效，便于看懂这一回合究竟用了什么配置。
- 遇到上下文溢出时，可从提示中开启压缩，供下一回合使用。

镜头应建立可见的因果：**打开 Skill → 发送真实任务 → 时间线出现 Skill 加载事件。** 积木组装可以作为品牌动画，但具体变化必须对应实际产品能力。

全量版使用 DeepSeek Harness 原生执行循环，在相同桌面界面提供更完整的工具与任务组织能力。

| 能力 | 当前产品事实 |
|---|---|

| 文档及图像相关读取 | 提供相应工具路径；实际理解能力取决于选用模型和输入支持 |
| 联网搜索 + 网页读取 | 搜索网页线索并读取内容；当前搜索接口需要可用的 DeepSeek Key |
| Skill 与待办 | 按任务加载指南，管理任务清单 |
| 子 Agent 与上下文分支 | 普通子任务，以及继承主对话上下文的子 Agent |
| 工作流 | 组织多步骤、多子任务的执行过程 |
| 上下文压缩 | 支持较长任务的上下文管理 |
| 长期目标 | 保存目标和进展，让多个回合围绕同一目标推进 |

### E. X 光：看见一次回答如何发生【现有】

**宣传表达：回答展开之后，还有一个值得探索的世界。**

X 光将记录到的真实执行过程展示给用户。它的五个视图是：

| 视图 | 用户能看见什么 | 适合的镜头 |
|---|---|---|
| 时间线 | 模型请求与响应、工具调用、参数与结果、状态、耗时、错误、审批、Skill、压缩、子任务和工作流相关事件 | 一条细线逐渐展开，镜头跟随一项真实调用 |
| 提示词 | 已记录的提示词组成、分段与来源信息、相关能力，支持前后回合对照 | 提示词由不同来源的卡片组成，突出一处变化 |
| 上下文 | 已记录的系统提示、工具定义、用户消息、历史回答、工具结果和摘要等组成及容量信息 | 上下文块随请求变化，某份工具输出被高亮 |
| Token 账单 | 请求用量、缓存、关联子任务，以及内容归因估算 | 从总量推进到一次请求，再到具体来源 |
| 原始请求 | 已记录、已脱敏的序列化请求数据；可复制检查，截断与缺失状态可见 | 短暂进入进阶视图，强调信息可以追溯 |

更多交互：

- 选择历史回合，或跟随最新运行。
- 切换新手与进阶阅读模式。
- 调整面板宽度，在工作与观察之间分配空间。
- 展开工具参数、结果和错误，定位事件之间的关系。
- 在采集完整时查看主任务、子任务及关联执行记录。
- 查看可用的提示词来源路径，复制已脱敏内容；支持的本地来源可进一步打开。
- 对比两侧各自进入 X 光，查看具体步骤差异。
- 数据缺失、截断或采集范围不足时显示真实状态。

这里展示的是 harness 及模型接口层记录到的过程。Pi 与 DSH 的采集粒度不同，例如 DSH 不提供与 Pi 完全相同的提示词来源分段。**不能把 X 光描绘成读取模型神经网络、隐藏思维或全部内部状态。**

### F. 随手点开，就能理解【现有】

**宣传表达：好奇的那一刻，正是学习开始的地方。**

| 功能 | 体验 |
|---|---|
| 「这是什么」 | 查看本地知识说明，解释当前术语或事件，不额外调用模型 |
| 「结合这一步详细讲讲」 | 用户主动请求模型结合选中步骤解释，传入限定范围的相关信息 |
| 独立讲解 | 讲解与当前任务对话分开，不替用户继续执行工具 |
| 讲解控制 | 支持流式显示、取消、重试及已有讲解缓存复用 |
| 能力概念对照 | 将 Skill、压缩、子 Agent 等概念与其他常见工具的使用经验联系起来 |

最适合的画面是从一项看不懂的事件轻点进入简明解释，然后回到自己的任务。无需在片中展示长篇教学文本。

### G. 本轮值得看的一幕【现有，新增主角功能】

**宣传表达：精彩的细节，轻轻提醒你。**

任务结束后，如果本轮真实记录中出现合适事件，回答下方会出现一张安静的小卡：

- 工具报错之后，发生了不同的工具调用。
- 本回合第一次加载了一项 Skill。
- 对话上下文在这里发生了压缩。

点击卡片，直接跳转并高亮对应事件。每回合最多一张，可单独收起，也可在设置中关闭。规则判断和卡片文案在本地完成，**生成与查看这张卡不额外消耗模型 Token**。

这是非常适合开场或转场的细节：用户原本只想完成任务，一张卡片把他带进了 Agent 的执行过程。

拍摄必须遵循真实事件：有不同调用不代表问题已经解决；「第一次」指本回合首次加载，不能当作用户一生第一次。

### H. Token 去哪儿了【现有，新增主角功能】

**宣传表达：看懂每一轮的信息开销，让优化有据可依。**

| 功能 | 帮用户回答的问题 |
|---|---|
| 模型报告用量 | 这一轮实际报告了多少输入、输出、缓存读取和缓存写入？ |
| 高输入请求排行 | 哪几次请求输入最多？ |
| 工具输出归因 | 哪份工具结果占用了较多上下文？来自哪个已记录工具或文件？ |
| 出现次数与累计估算 | 一份内容进入了哪些请求，累计形成多少估算上下文占用？ |
| 重复历史识别 | 哪些完全相同的历史消息在后续请求中再次出现？ |
| 父子任务统计 | 可关联的子 Agent 用量如何组成，如何避免重复计算？ |
| 缓存拆分 | 缓存命中与写入如何出现在供应商报告中？ |
| 点击溯源 | 从用量项回到对应请求或事件 |
| 「先搜索，再试一次」 | 把一个观察变成可以动手验证的读取策略实验 |

账单明确区分 **模型报告的实测用量** 与 **按内容推算的归因估算**。无法完整采集的子任务不拼成假精确总量；供应商没有报告的项显示未提供。它不是人民币账单，也不会把历史再次出现直接判断成浪费。

「先搜索，再试一次」的实际流程：

1. 用户查看任务、模型和额外调用提示，按需要补充上下文。
2. 从当前工作区创建两份新的独立副本。
3. 两侧使用相同 Pi、模型和能力基线；一侧要求直接读取相关文件，另一侧要求先搜索再分段读取。
4. 用户点击「同时运行」，完成真实任务，再对照结果、调用、Token 和文件变化。

查看账单、预览和建立副本不会调用模型；运行实验会使用用户配置的模型。实验比较的是新运行，不能伪装成恢复旧回合的精确重放。**宣传重点是学会验证自己的选择，不能承诺搜索策略每次更省 Token、或 Token 更少就质量更高。**

### I. 双路对比：让差异自己呈现【现有】

**宣传表达：同一个起点，展开两种可能。**

当前有三种对比方式：

| 对比方式 | 保持相同的部分 | 用户观察的变化 |
|---|---|---|
| 同模型 · Pi 与 DSH | 任务、模型、工作区起点 | harness 如何组织工具与执行过程；可为本次比较开启 Pi 全部扩展能力 |
| 同 Pi 能力 · 两个模型 | 任务、Pi 能力配置、工作区起点 | 更换模型后，回答、工具选择与产物有什么差异 |
| 同模型 · 两种读取策略 | 任务、Pi、模型、能力配置、工作区起点 | 直接读相关文件与先搜索再分段读，实际结果与开销如何 |

完整体验：

- 基于同一工作区起点建立两份独立副本与会话，显示复制范围和限制。
- 一次发送相同任务，两侧并排流式运行。
- 查看每一侧的运行状态、审批来源和错误；支持停止两侧。
- 保留对比历史与多轮对话，重新打开后继续。
- 对照回答、模型调用、工具调用、子任务、压缩、Token、耗时及文件变化等已获得指标。
- 进入两侧各自的 X 光和 Token 账单；查看并排执行事件。
- 查看新增、修改、删除文件及可展示的文本差异，识别二进制变化。
- 用户明确选择后，采用一侧的整组文件变化；写回前检查原工作区是否产生冲突。
- 按需让模型解释差异；这是用户主动触发的额外调用，可复用已有结果。
- 已完成且统计完整的 **Pi／DSH 对比** 可以生成社区分享卡。

对比的价值是形成判断。它不预设全量版必胜，也不自动给学生打分。当前社区分享范围不应扩大描述为「所有对比与全部 Trace 一键公开」。

### J. 30 个探索成就【现有】

**宣传表达：把每一次“原来如此”，留下来。**

成就根据真实事件与操作在本地解锁，包含隐藏发现项、解锁通知、解锁时间，以及存在关联记录时回到原回合的入口。判断无需额外调用模型。学习记录可导出，成就可进入社区发帖流程。

| 主题 | 当前成就名称 |
|---|---|
| 动手与掌控 · 8 项 | 初次见面、动起手来、命令行、落笔、我说了算、说不、一心多用、马拉松 |
| 看见与追问 · 6 项 | 透视眼、看穿提示词、原汁原味、好奇、刨根问底、请讲详细 |
| 能力成长 · 5 项 | 第一项能力、成长期、接近完全体、技能上身、自定义技能 |
| 复杂任务 · 6 项 | 压缩饼干、撞墙、分身术、流水线、清单控、上网冲浪 |
| 对照探索 · 5 项 | 擂台、看出门道、常胜擂台、一针见血、换个脑子 |

「接近完全体」需要能力真的被使用；「自定义技能」对应加载非内置 Skill；「常胜擂台」是徽章名称，不应解释为胜率。成就记录探索经历，不代表考试分数或专业资格。导出内容是成就、能力与计数等学习记录，不是整段私密对话。

### K. 掌控感与日常体验【现有】

- 权限模式：每次询问、工作区写入、放开权限，适用于不同工作方式。
- 工具审批：查看工具名称与参数，允许本次或拒绝，理解操作实际影响。
- 可停止的执行过程、明确的失败与取消状态。
- 本地会话、配置和学习记录；原始请求记录可由用户控制开关。
- 浅色、深色、跟随系统主题；面板与窄窗口布局适配。
- 发送等常用键盘操作，工作区与模型状态持续可见。
- 插件市场入口：浏览 Pi 社区热门插件、GitHub 项目和社区讨论，发现第三方扩展。
- CLI 与可扩展插件体系：提供进阶使用和开发路径。

本地保存不等于离线推理；使用在线模型时仍会发送执行任务所需的信息。能力开关是工具与行为配置，不等于网络防火墙。插件市场当前主要提供发现与外部入口，不能拍成已有完整的一键安装商店。

## 04｜社区：把一个人的探索，变成共同创造

**社区必须在主片中拥有完整段落。建议 90 秒主片至少给予 18 秒。**

它承接的是整条体验：学生带着自己的作品、对比结果和发现走进社区，在讨论中获得新的问题，再回到下一次创造。

> **你的作品，有人打开。你的问题，有人接着想。你的发现，有人继续探索。**

社区是独立网站，也能嵌入 BuildMe 桌面端。以下功能当前均有实现；对外访问需要配置并部署正式站点。

### A. 进入社区与个人身份【现有／需配置站点】

- 无需登录浏览公开内容与搜索。
- 邀请码注册、用户名与密码登录。
- GitHub 授权登录和账户绑定入口，配置 OAuth 后启用。
- 个人头像上传、默认头像、用户名、简介与密码设置。
- 个人主页汇总帖子、回复和作品。
- 收藏与草稿由本人管理。
- App 内独立社区登录状态，重新启动后可以保留。

### B. 分享一条链接，也能写一篇完整发现【现有】

- 五个初始板块：**分享、文章、问答、作品、闲聊**。
- 快速分享链接：标题、来源卡片、缩略图和重复链接提醒。
- Markdown 长文：标题、正文、代码块、代码高亮与复制、目录。
- 编辑器工具栏、即时预览与完整预览。
- 图片上传、粘贴和拖入，生成适合显示的图片与缩略图。
- 表情与标签；支持申请新标签，供管理流程处理。
- 本地自动保存草稿与服务器草稿，支持恢复、编辑和删除。
- 已发布内容可编辑、查看最近十次版本记录或软删除。
- 外部资料保留原文访问入口。

适合展示的帖子主题：「这个 Skill 为什么触发了」「同一个任务换模型后发生了什么」「我的第一个可用工具」。这些是创作主题建议，不代表已有真实用户帖子。

### C. 围绕具体问题讨论【现有】

- 按楼层组织回复，回复某一楼、展开相关讨论、引用内容。
- @ 用户联想，便于邀请具体同学加入讨论。
- 回复支持 Markdown、代码、图片与表情。
- 编辑、删除自己的回复；复制稳定楼层链接。
- 楼层定位与滑块；长讨论按需加载。
- 帖子点赞，帖子和回复的 8 种表情回应。
- 私人收藏，把有价值的讨论留给以后。
- 回复、@、点赞和表情等通知；合并相关通知、显示未读数、跳转具体楼层、全部已读。

社区当前采用论坛式交流；群聊、私信、关注关系不属于已实现范围。画面应围绕作品与讨论自然展开。

### D. 发现值得看的内容【现有】

- 首页热门内容与热门阅读。
- 最新内容按活跃或发布时间查看。
- 精华、精选与点赞榜等内容入口。
- 按周、月、全部，以及板块和标签筛选。
- 搜索帖子、回复和用户。
- 支持作者、标签、带引号的短语及筛选条件，提供高亮与输入建议。
- 板块页、标签页、个人内容页。
- 全站、板块与标签的 RSS 订阅。
- 关于、社区规则与可配置下载页。

内容热度用于发现帖子，不等同于对学生能力或学习成绩排名。

### E. 作品墙：让创造被看见【现有】

**宣传表达：这一面墙，装得下更多人的可能。**

| 功能 | 用户体验 |
|---|---|
| 作品发布 | 用一张封面和一句话介绍自己的作品 |
| 封面编辑 | 上传封面，调整位置与缩放，呈现统一比例 |
| 制作工具标签 | 标注用 BuildMe、Claude Code、Codex、Cursor 或其他工具创作 |
| 体验与源码入口 | 作者可提供外部演示链接和源码地址 |
| 作品展示 | 网格作品墙，支持最受欢迎与最新查看 |
| 筛选 | 按制作工具、周、月或全部时间范围浏览 |
| 精选 | 管理员精选，首页展示及下载页精选作品 |
| 作者作品集 | 从个人主页继续看同一位创作者的作品 |
| 讨论与回应 | 沿用帖子的回复、点赞与互动记录 |

作品墙欢迎不同工具制作的作品。工具标签是作者说明创作方式，不能延伸为 BuildMe 已直接控制这些外部 Agent，或可以自动读取它们的内部执行过程。演示与源码链接指向作者提供的站点，社区不自动为作品部署服务。

### F. 从桌面到社区【现有／需配置站点】

- App 侧栏直接打开嵌入式社区。
- 深浅主题同步、加载进度、离线提示和失败重试。
- 显示社区未读消息，外部链接在系统浏览器打开。
- 已完成且统计完整的 Pi／DSH 对比：从差异摘要生成社区分享内容。
- 成就页或解锁通知：将探索成就带进发帖流程。
- 分享先进入编辑器；用户可以写自己的观察、保存草稿，再确认发布。
- 未登录时可登录后恢复分享内容。
- 分享卡仅携带规定的名称与统计字段，不自动上传密钥、完整聊天、文件正文或原始 Trace。

最值得拍的一条路径：**双路结果 → 分享卡 → 一句话写下自己的发现 → 发布 → 同学在具体楼层回应。**

### G. 为持续交流准备的管理能力【现有，制作方参考】

- 首帖审核、举报、多人举报自动隐藏、恢复与内容审核队列。
- 屏蔽词、重复内容和部分广告行为处理，用户资料审核。
- 管理员与版主角色，封禁、禁言和角色管理。
- 邀请码、板块、标签、制作工具列表和站点设置管理。
- 精选文章与作品、真实站点统计、管理操作记录。
- 桌面及手机布局、浅深主题、基础表单渐进增强。
- 独立社区服务、本地图片存储与可配置 OSS 存储。
- 部署、数据迁移、备份恢复、图片清理与健康检查工具。

社区不依赖服务器侧模型生成内容或推荐，不会因为浏览与讨论产生社区服务器的模型调用费用；普通托管和存储成本仍然存在。这些支撑能力用于长期运营，通常不进入主片旁白。

## 05｜未来功能：值得延展的 16 个方向

以下均为 **【未来概念】**，不是发布时间承诺。「本轮值得看的一幕」和「Token 去哪儿了」已属于现有功能，不再列入未来清单。部分概念已有基础能力，表中明确区分新增部分。

| 未来功能 | 想带给用户的体验 | 可用的概念文案与画面 |
|---|---|---|
| 1. 先看作品，再揭晓配置 | 先看两侧成果形成自己的判断，再揭晓模型、引擎与配置；建立结果优先的对比体验 | **先看见作品，再认识它的来路。** 两个作品先出现，配置卡最后翻开 |
| 2. 只改一项，再跑一次 | 将通用的单变量实验扩展到 Skill、计划、提示词或能力开关；当前已有读取策略对比这一具体入口 | **一个改变，会带来什么？** 只高亮一个开关，两条执行路线开始分化 |
| 3. Skill 试衣间 | 调整 Skill 的触发描述、步骤、参考资源和验证要求，在真实任务中比较不同版本 | **好方法，也值得反复打磨。** 一处 Skill 改动连接到一次不同的工具调用 |
| 4. 借走同学的 Agent 配方 | 分享选定能力、Skill 与提示词配置，查看差异，再在自己的副本中试用 | **让一种好方法，遇见下一个创造者。** 社区配方卡展开成可检查的能力组合 |
| 5. 这一刻，它能看见什么 | 基于现有上下文视图，增加按请求时间定位的信息纳入视图 | **把这一刻的上下文，展开给你看。** 时间游标移动，当前请求的信息块随之变化 |
| 6. 这条规则从哪里来 | 基于现有提示词来源信息，进一步追踪选中规则的来源、加载时机和生效范围 | **每一条规则，都有来处。** 从一句规则回到对应文件与加载位置 |
| 7. “做完了”的证据 | 汇集文件变化、检查命令与结果，结合用户选择的验收条件查看完成证据 | **让完成，有迹可循。** 作品旁边展开真实检查结果 |
| 8. 我的发现卡 | 学生主动记录自己的猜想、改动与观察，选择证据分享到社区 | **把一次发现，讲给更多人。** 观察、证据、结论组成一张可讨论的卡；区别于现有自动回合提示卡 |
| 9. 作品的成长过程 | 选择若干版本、截图和改动，整理成作品发展故事 | **让作品，也讲述它如何长大。** 三个实际版本连续变化，不做后台持续录屏 |
| 10. 从经历长出来的知识地图 | 将自己真正经历过的 Skill、压缩、缓存、子 Agent 等事件连接成探索地图 | **你走过的每一步，都在连接。** 地图节点来自真实记录，不模拟考试分数 |
| 11. 一句话怎样变成 Token | 使用明确支持、版本可追溯的本地 tokenizer，把文字切分与 Token 对应起来 | **信息的颗粒，也可以看见。** 一句话逐段显出切分边界 |
| 12. 下一步，我来选 | 在实验副本中暂停于某个执行步骤，查看、调整下一步行动，再继续运行 | **这一刻，把选择交给你。** 用户改变一个具体行动；当前工具审批不能冒充这一完整体验 |
| 13. 从这里走另一条路 | 建立真实检查点和状态恢复能力，从选中位置分出另一条执行路线 | **一个起点，还有另一种走法。** 时间线分支；当前历史查看不等于可以恢复执行状态 |
| 14. 压缩之后，它还记得吗 | 对照压缩前信息、摘要和选定约束，再观察后续任务行为 | **压缩了什么，留下了什么？** 一段长历史汇入摘要，重要约束被逐项检查 |
| 15. 在副本里，给它制造一点意外 | 在明确标记的实验中注入工具失败或不完整结果，观察 Agent 如何应对 | **遇见意外，才看见应对。** 工具错误后出现不同执行路径；画面标注模拟实验 |
| 16. 把外面的 Agent 带进 X 光 | 为支持格式的外部导出日志建立适配器，注明工具版本、字段与缺失信息 | **让更多执行过程，可以被理解。** 一份支持的日志进入统一观察视图；并非已能无差别解析所有 Agent |

### 最适合单独做概念预告的组合

**Skill 试衣间 → Agent 配方 → 作品成长过程 → 知识地图。**

这四项连接个人实验、社区交流与长期成长，容易产生连续叙事。可以制作独立的 20–30 秒概念短片，以「未来探索方向 / Concept」清楚标识。现有功能主片优先讲清今天已经能体验到的价值。

## 06｜商业片创意方向

### 推荐主题：《看见，才开始掌握》

一位学生完成自己的第一个小作品。回答结束后，一张轻巧的发现卡吸引了他的注意。他打开 X 光，看见 Skill 被加载、工具被调用、信息如何进入请求。他试着打开一项能力，再让两种 Agent 面对同一个问题。最终，他把作品和发现带到社区。另一个学生打开帖子，开始新的创造。

影片里的成长由连续的动作呈现：**做出来 → 点开看 → 动手改 → 对着比 → 分享出去。**

真正的主角是用户的好奇心与掌控感。BuildMe 让这些变化发生在可见的界面中。

### 「苹果感」的具体执行方式

我们借鉴的是高品质产品广告的克制、精度和对产品的自信。以下是本片自己的视觉与节奏方向：

| 维度 | 执行要求 |
|---|---|
| 画面中心 | 产品、作品和用户操作；每个镜头集中表达一个变化 |
| 构图 | 大面积留白、明确焦点，界面局部可以占据整个画面 |
| 品牌色 | 冷灰中性底；陶土色代表「我的 Agent」；X 光使用蓝色；全量版用石墨色 |
| 图形母题 | 等距积木、薄片与有秩序的结构；基础积木可以贯穿片头、能力组装、成就与片尾 |
| UI | 使用真实页面或忠实重建的产品界面，关键名称保持一致，放大后仍清晰可读 |
| 动效 | 通过操作建立因果：一次点击引起一次明确变化；少量精确的位移、缩放、层次展开 |
| 节奏 | 开头留出好奇，中段逐渐加速，社区段落舒展，片尾留一拍让品牌成立 |
| 文字 | 大字、短句，一次出现一个观点；长解释进入声音或制作附注 |
| 声音 | 清晰的点击、积木落位、轻微机械与空间音效；音乐逐步建立节奏，给关键操作留白 |
| 人的温度 | 可以出现手、目光和短暂反应；也可完全通过真实作品、署名与讨论传达人的存在 |
| 作品素材 | 有差异、有完成度的真实作品；演示数据如需重建，明确标记为演示 |

避免使用泛化的蓝紫霓虹宇宙、旋转大脑、不断飘动的代码雨、无意义光束或连续堆叠抽象技术名词。无需照搬任何已有广告的镜头、音乐或标识；建立 BuildMe 自己的视觉记忆。

### 一条连续的视觉线索

一块陶土色积木出现，组成「我的 Agent」；蓝色扫描线展开真实 Trace；同一块积木在对比中形成两条路径；它变成探索徽章，进入社区卡片；片尾，多块积木围绕 BuildMe 聚合。

积木承担品牌识别，真实 UI 承担功能证明。这样的组合可以让影片兼具质感与可信度。

## 07｜90 秒主片分镜建议

以下是可进一步创作的导演稿。主片仅使用现有能力。旁白不必覆盖每一秒，让声音和界面动作承担一部分叙事。

| 时间 | 画面与动作 | 屏幕短句 | 旁白建议 | 素材性质 |
|---|---|---|---|---|
| 00–06 秒 | 冷灰空间，一块陶土色积木落位。输入框出现一句真实任务，光标停顿后发送 | 从一个想法开始 | 「一个想法，能走多远？」 | 品牌动画 + 真实输入 |
| 06–14 秒 | 真实工具执行与文件变化，随后展示可操作的小作品；镜头留给一次有满足感的交互 | 让它发生 | 「先动手，把它做出来。」 | 产品与作品实拍 |
| 14–21 秒 | 回答结束，下方出现「本轮值得看的一幕」。点击，定位到本轮 Skill 加载事件 | 原来，这里还有一幕 | 「然后，跟着好奇心，多看一步。」 | 真实发现卡与跳转 |
| 21–33 秒 | X 光面板展开；工具参数、提示词组成、上下文依次出现。蓝色只标记当前重点 | 看见每一步 | 「看见提示词如何组成，工具如何调用，信息如何进入下一次请求。」 | 真实 Trace，适度动效分层 |
| 33–44 秒 | 「我的 Agent」打开，启用子 Agent 或 Skill。回到任务，出现对应执行事件；积木同步增加 | 能力，由你打开 | 「一项能力，一次尝试。你的 Agent，开始有了你的选择。」 | 开关与真实使用配对 |
| 44–55 秒 | 同一任务分屏进入 Pi／DSH；两条调用路线展开，最后停在产物和文件差异 | 同一个起点，两种可能 | 「同一个问题，换一种做法。把差异，放在一起看。」 | 已完成真实对比 |

## 09｜给 Claude 的直接制作指令

**Claude，请基于本文件，创作 BuildMe 的产品商业宣传片。你承担创意导演、广告文案和动效导演的职责。**

我们的目标观众是已经接触 AI、想提升 Vibe Coding 能力，却还没有真正理解 Agent 如何工作的学生与年轻创作者。影片要让他们产生三个清晰感受：这个产品能帮我做出东西；我可以亲眼看见并改变 Agent 的工作方式；我的作品和发现可以在社区里被看见。

主片建议 90 秒、16:9，以高品质产品商业片的标准创作。追求精确、克制、留白、触感、声音设计和明确的操作因果。品牌主张采用「把 AI 的能力，变成你的能力」。围绕真实任务、X 光、能力开关、双路对比、发现卡与 Token 账单、社区组织故事。社区至少有 18 秒完整叙事，包含作品、具体讨论或分享路径。

请先完成以下内容，并保持每份内容可以用于实际制作：

1. **最终创意概念：** 一句话主题、观众情绪变化、影片贯穿的视觉线索。可以优化本文件建议，但必须保留产品事实与社区分量。
2. **90 秒逐镜分镜表：** 每镜的时长、构图、镜头运动、具体 UI 状态、用户动作、动效、屏幕文字、旁白、音效和转场。每一镜说明使用真实录屏、忠实 UI 重建、品牌动画还是概念画面。
3. **最终旁白与字幕：** 中文为主，旁白自然可朗读，按实际节奏计时；字幕短而有力，避免堆叠 Agent 术语。
4. **美术与声音方案：** 颜色、字体层级、材质、光影、积木母题、界面尺度、音乐起伏与关键操作音效。
5. **素材采集清单：** 精确到要打开哪一页、触发哪一个真实事件、需要哪类作品和社区内容。尚无素材时给出明确占位，不编造成功记录与用户数量。
6. **30 秒与 15 秒剪辑方案：** 重新组织叙事，保留清晰的产品记忆与社区露出。
7. **未来概念短片可选案：** 如使用第 05 节，仅作为独立概念预告，明确标注未来方向。

如果当前环境可以制作视频，继续依据批准范围或当前任务授权制作可预览成片与可编辑源文件；如果缺少具体素材，先交付完整分镜、旁白、镜头素材需求与可执行制作工程方案。不要仅给一段泛泛创意说明。

产品事实约束：

- 所有功能状态以本文件的「现有／需配置／未来概念」为准。
- X 光展示真实记录的执行过程；不描述为读出隐藏思维、神经网络或一切内部状态。

- 主片：90 秒左右，16:9，优先 4K 交付；实际录屏分辨率不足时不要通过模糊放大掩盖。
- 社交版：30 秒、15 秒；可额外适配 9:16，重新排版 UI 局部。
- 提供纯净版、带字幕版、封面与片尾静帧。
- 保留可编辑工程、字体与音乐授权信息、镜头素材对应表。
- 功能概念动画与真实 UI 有清楚的制作分类，方便未来更新产品画面。
