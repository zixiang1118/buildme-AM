01 / COMPARE

同一个问题，
让两种做法同时展开。

像日常聊天一样持续追问。两个 Agent 同时回答，各自记住上下文，你可以沿着每一轮看到差异如何产生。

同一问题，同一工作区基线一次输入 → 两侧同时开始
Pi自由组合能力
各自保留上下文与文件
DSH原生 Agent 循环
各自保留上下文与文件

并排查看回答、执行过程与文件差异

比较结果，也比较做事的方法。

模型决定一部分能力，围绕模型的工具、上下文与执行机制也同样重要。BuildMe 让这些差异可以被观察。

  • 两种引擎，一起做事Pi 与 DeepSeek Harness（DSH）并行运行。
  • 不同模型，认真比较明确选择两条模型连接，也可以比较文件读取策略。
  • 自动执行，按需采用双路默认免工具审批；两侧使用独立副本，采用改动到原文件仍需确认。

同一模型的输出也有随机性；单次结果不能证明差异全部来自 harness。强制只读的工作区仍禁止写入与命令执行。

02 / SEE THROUGH

把黑盒打开。
看见答案背后的工作。

提示词从哪里来？工具到底做了什么？上下文为何变短？X 光把实际运行记录带到眼前，从一次具体任务理解 Agent，而不是只记住术语。

查看模型实际返回的推理内容与 Token 用量。提供商未返回的数据会明确标注；估算会标明，缺失不会伪装成零。

阅读架构与运行机制 ↗
X 光 · 回合时间线结构示意
  1. 组装提示词能力说明 · Skill · 工作区上下文
    提示词来源 → 能力配置 → 可用工具
    查看这一步如何影响后续执行
  2. 模型请求查看脱敏后的请求与实际返回内容
  3. 工具执行工具名称、参数与结果，关联到本轮任务
  4. 上下文处理按实际压缩或裁剪事件记录变化

基于真实 Trace 的记录；未提供、估算与精确值分开呈现。

WHY BUILDME

用 AI 做出东西。
也让自己成长。

我们相信，好的 Agent 工具应该让人越来越有判断力。看懂它如何组织上下文，知道何时需要工具，理解不同方法的取舍，才有可能把一次好结果变成可复用的能力。

BuildMe 把创作和学习放在同一张桌面上。你可以写代码、整理资料、处理文件、搭建自动化，也可以停下来，看看它刚才到底是怎么做的。
