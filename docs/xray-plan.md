# BuildMe 分批实施计划

更新：2026-10-05。以 [PRD](./prd-xray-capabilities-compare.md) 为需求基准，以 [实际交付与验收](./xray-progress.md) 为进度依据。

## 执行方式

按用户已批准的 M2 → M3 → M4 → M5 计划连续实施，每批先实现、针对性验收并记录，再进入下一批。功能以真实运行链路为准，界面、持久化、运行时效果和出错状态一起考虑。未验证的部分保留明确边界；批次失败先修复；日常选择直接采用推荐方案。里程碑完成时运行 PRD 指定的五项检查并提交本地 Git，不自动发布或推送。

保留现有 Cordis / Loader / Include / Profile / Bundle 和两个引擎。复用 Trace、提示词快照和公共讲解文案，避免为界面增加重复的执行链。原有未提交改动单独保留。

## 已完成阶段

- M0：统一 Trace、持久化、脱敏和能力事件采集。
- M1：统计入口、实时抽屉、四个检查页、本地讲解。本轮完成最后一批与桌面验收。

## M2 能力开关

### 第一批：能力定义和运行时过滤

交付 `src/core/capabilities.ts` 唯一注册表；在运行选项与工具作用域传递能力快照；处理 workflow / subagents 依赖。桌面界面在后续批次接入，第一批不显示尚无实际效果的开关。

验收：遍历所有能力，核对允许的工具集合；不传 capabilities 时保持现有行为；core 不可移除；workflow 自动开启 subagents，关闭 subagents 同时关闭 workflow。子 Agent 继承父回合能力，但移除 subagents 与 workflow，禁止继续委派；未传配置的旧调用保留 edition 行为。

### 第二批：提示词与压缩行为

将能力用法拆成有来源标识的独立段落，复用当前提示词注册表；工具列表、提示词与实际运行能力一致。接通 compaction 关闭时直接放行与 overflow 事件。同步调整 DSH 提示词拼装。

验收：能力关闭后对应工具和指令都消失，重新开启后恢复；两回合快照差异正确；小上下文下触发真实 overflow；DSH 提示词完整，相关现有测试通过。

### 第三批：用户可操作的能力面板

接入桌面配置、首次选择与「我的 Agent」面板；显示九项开关和五项完全体专属说明；共享知识文案；示例只填入输入框；从 Trace 读取实际使用次数。锁定卡的对比入口与 M4 的依赖明确记录，不能用假对比冒充完成。

验收：运行中切换不改变当前回合，下一回合生效；重启保持；依赖变化有提示；首次选择、示例、超限提示和浅深主题/键盘操作可用。结合真实 Electron 检查配置 → 运行 → Trace → X 光提示词差异的完整链路，关闭 M1 B-5 中能力开关联动的跨里程碑检查项。

M2 收尾逐条核对 C-1 至 C-10；必要时拆成更多轮，不为赶进度合并未经验证的功能。

商业产品质量在每批落实为：真实能力、清晰状态、稳定交互、可恢复的历史、可理解的失败信息和可复现的验证。尚未做真实模型与跨平台测试的地方，不标注为生产验收通过。

## 已批准的后续细化（2026-10-05）

### M3：成就

1. 30 条确定性规则统一消费 Trace 和 UI 事件；回合/事件身份去重，重启不重复计数。使用次数来自成功工具结果或真实压缩/裁剪事件。`skill-author` 保留 ID、名称改为「自定义技能」，依据成功加载非内置 Skill，不推断作者。审批拒绝、取消、超时分开。
2. 成就页、未解锁提示、按顺序通知、跳转触发回合；无关联或已清理必须说明。导出仅含成就、能力和计数器。对比及深入讲解规则先测试，随 M4/M5 接真实事件。

### M4：双引擎对比

1. 根据安装包核实 DSH llm/stream、工具、会话、审批和子任务事件并记录依据。bridge trace 通知统一脱敏和存储，实时与结束回填去重，父子用量分开；精确/估算/不可用据实标注。
2. 同基线独立副本排除 .git、node_modules、超过 50 MiB 文件，总量超过 300 MiB 强制只读。不跟随外部符号链接。写入限制副本，命令通过现有沙箱且无法隔离即拒绝；只读拒绝写入和命令且子任务继承。完整新增/修改/删除/文本 diff/二进制清单，采用前确认并比较基线哈希，有冲突停止全部写回。删除对比或七天过期清理专属副本，保留历史回答和差异，失效副本禁用采用。
3. compareGroupId 关联两会话、连接/能力快照、工作区和回合。Build 可独立启动 DSH，同模型默认同连接，Pi 全开仅本次；独立输出/失败，取消双方及子任务，审批标来源。可继续提问、重启恢复，中断如实显示。
4. 从 Trace 去重汇总父子调用/工具集/子任务/压缩/tokens/耗时/文件变化，缺值不补零或计算差值，零基准不算百分比。按 round 并列时间线，窄屏上下排列。措辞仅描述同模型不同 harness 的表现，不保证差异完全由 harness 导致。接通成就与专属能力入口。

### M5：深入讲解、模型对比和最终验收

1. 主进程按回合/事件 ID 读取脱敏记录，使用当前连接独立流式讲解，可取消/明确错误；短输入、有限输出，不自动换付费模型，不写聊天、不创建 Agent 回合。成功内容按事件内容/模型/讲解版本缓存。
2. 差异总结只发统计和事件摘要，产出 3–5 条有数字依据的结论。模型对比明确选择两连接，用两独立 Pi 会话、同能力和同基线，复用对比链路。
3. 各模块验收覆盖依赖/快照/旧行为、30 条正反规则/去重/导出、只读/采用冲突/取消/单侧失败/恢复/清理、讲解流式/取消/缓存/错误/历史不变。固定假模型测 Trace 开销，200 事件渲染 300ms 门槛；记录测量条件。
4. 隔离 Electron 数据完成端到端，不访问真实模型 API、不删用户真实数据。macOS 和 Windows 独立验证；未实际运行的平台保留待验证。

每个里程碑通过五项检查：`pnpm test`、`pnpm typecheck`、`pnpm test:typecheck`、`pnpm lint`、`pnpm build`，更新证据并提交本地 Git。社区、打包、发布、部署与推送不在范围内。
